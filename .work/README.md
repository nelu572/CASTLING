# 임시 작업 자료

작업 중 생성하는 스크린샷, 화면 비교, 참고 이미지 복사본, 시안, 일회성 검사 코드·JSON·로그는 이 폴더에 모은다. 이 README와 `.work` 루트는 유지하고, 작업 자료와 작업별 하위 폴더는 아래 기준으로 작업 중에 정리한다.

## 저장 구조

`.work/<날짜>-<작업명>/`을 실제 작업 자료가 필요할 때 만든다. 예를 들어 `.work/20261006-camera-check/`에 `README.md`, `01-before-play.png`, `02-after-play.png`, `console.log`, `result.json`을 함께 둘 수 있다. 필요한 파일만 생성하며, 파일 종류마다 하위 폴더를 미리 만들지 않는다. 같은 작업명과 날짜가 겹치면 설명이나 순번으로 구분해 기존 자료를 덮어쓰지 않는다.

- `.work/README.md`는 Git 보존 대상이다.
- 작업별 폴더와 그 안의 파일은 README까지 모두 Git에서 제외한다. 작업 자료를 커밋·PR에 섞지 않는다.
- Unity MCP 캡처는 `output_folder`를 해당 작업 폴더로 지정하고 반환된 저장 경로를 확인한다. 기타 도구의 캡처·로그·결과 출력도 같은 폴더로 지정한다.
- 도구 기본 출력이 다른 곳에 생겼다면 이번 작업에서 만든 파일인지 확인하고 이곳으로 정리한다. Unity가 이미 Import한 파일의 이동·삭제는 Unity MCP로 처리하며, 기존 에셋이나 `.meta`를 직접 정리하지 않는다. Unity 자체의 `Library`·`Temp`·`Logs`는 도구가 관리하는 위치를 유지한다.

## 작업별 안내 양식

작업 폴더의 README에는 아래 내용을 실제 값으로 적는다. [자료 양식](../.templates/RESOURCE_TEMPLATE/template.md)을 더 자세한 안내에 사용할 수 있다.

```markdown
# 작업명

- 목적:
- 상태: 진행 중 / 검토 대기 / 문제 미해결 / 정리 가능
- 파일과 용도:
- 확인 조건: 프로젝트·씬·Edit/Play Mode·해상도·카메라·입력 등 관련 조건
- 보존할 자료: 없으면 없음, 있으면 파일·이유·보존 종료 조건
- 정리 조건: 검증 완료, 사용자 검토 완료, 문제 해결 등
```

스크린샷 전후 비교는 같은 조건으로 하고, 실제 플레이와 구도 확인용 배치를 구분한다. 파일 이름으로 전후·장면·순서를 구분하고 필요한 조건만 README에 남긴다. 별도 JSON이나 캡처 색인을 의무로 만들지 않는다. 캡처 방식은 [Unity 하네스](../.codex/harness/UNITY.md)를 따른다.

## 정리 시점

정리는 작업 흐름 안에서 수행한다. 작업하는 동안 아래 시점마다 해당 작업 자료의 용도와 보존 종료 조건을 확인하고, 필요 없어진 자료를 별도 정리 요청 없이 정리한다. 이슈·PR이 열린 동안에도 끝난 검사의 불필요한 자료는 정리한다.

- 작업 시작·재개: 해당 작업의 README와 이전 보고에 남긴 자료의 상태·정리 조건을 확인한다. 조건이 충족됐고 정리 범위가 명확한 자료만 정리한다. 무관한 작업 폴더를 일괄 청소하지 않는다.
- 검사·구현 단락 종료: 쓸 수 없는 캡처, 중복 출력, 역할이 끝난 일회성 파일을 정리한다. 다음 비교·재검사·문제 재현에 필요한 자료는 유지한다.
- 검토 응답 처리: 사용자가 검토 완료를 명확히 알리거나 정해 둔 보존 종료 조건이 실제로 충족됐으면 해당 자료를 정리한다. 응답이 없거나 시간이 지났다는 이유로 검토 완료로 간주하지 않는다.
- 커밋·PR·완료 보고 전: 남길 자료를 필요한 범위로 줄이고, 보존 이유·정리 조건이 현재 상태와 맞는지 확인한다. 커밋·PR 요청이 없더라도 검사·구현 단락 뒤의 정리는 수행한다.

| 상태 | 보관·정리 기준 |
| --- | --- |
| 진행 중 | 다음 검사·비교에 필요한 자료를 유지한다. 실패한 캡처·중복 파일은 확인 후 정리하고, 비교에 쓰는 전후 원본은 남긴다. |
| 검토 대기 | 사용자 확인에 필요한 화면·파일만 유지한다. 작업 보고에서 파일 링크로 검토를 요청한 자료는 사용자가 볼 때까지 삭제하지 않는다. |
| 문제 미해결 | 재현·원인 분석에 필요한 최소 자료를 유지한다. 문제 해결 뒤 결과와 필요한 방법을 지침에 반영하고 정리한다. |
| 정리 가능 | 자료의 용도가 끝나고 검증 결과·필요한 방법을 기록했으며 필요한 사용자 검토가 끝났으면 해당 자료와 빈 하위 폴더를 삭제한다. 삭제한 파일을 열어 보라는 링크를 보고에 남기지 않는다. |
| 중단·취소 | 재개·인계·보존 요청이 있는 자료는 유지한다. 해당 작업에 필요 없어진 자료는 요청 범위에서 정리한다. |

위 시점에서 남길 자료가 바뀌면 작업별 README의 상태·파일과 용도·보존 종료 조건을 갱신한다. 사용자 검토 대기 등으로 남겼다면 작업 보고에 남은 경로·이유·정리 조건을 적고, 다음에 해당 작업을 이어갈 때 다시 확인한다. 정리 범위나 조건이 불명확한 자료는 유지하고 필요한 경우에만 확인한다. 파일이 오래됐다는 이유만으로 진행 중·검토 대기·보존 자료를 일괄 삭제하지 않는다.

## 보존할 내용

- 다음 작업에도 필요한 주의점·검사 방법은 하네스·작업 절차·사용 안내에 반영한다.
- 보존할 사용자 결정과 미확정 범위는 `.reference/records/`에 남긴다.
- 편집 가능한 아트 원본·생성 도구는 `Tools/Art/`에 사용 방법과 함께 둔다. 실제 게임 에셋은 `Assets/`에서 관리한다.
- 사용자가 자료 보존을 요청하면 대상과 용도에 맞는 정식 위치를 정해 필요한 파일만 보존한다. 임시 묶음 전체를 자동 승격하지 않는다. [자료 추가 기준과 양식](../.codex/harness/TEMPLATES.md)을 따른다.

## 삭제 범위와 사용 중인 파일

정리 전에 절대 경로가 이 작업의 `.work` 하위인지, 다른 작업·사용자 파일·보존 대상이 섞이지 않았는지 확인한다. 링크나 재분석 지점을 따라 다른 위치를 삭제하지 않는다. 해당 작업에서 만든 파일과 빈 작업 폴더만 제거하며, 이 README와 루트 폴더는 남긴다.

로그가 사용 중이면 보관 상태와 남은 경로를 보고하고, 프로그램 종료가 이미 허용된 범위인지 확인한 뒤 정상 종료 후 정리한다. 정리만을 위해 저장하지 않은 사용자 작업을 버리거나 프로세스를 강제 종료하지 않는다.
