# 독립 레벨과 보관 씬 제작 결정 기록

## 범위와 근거

- A·B는 **Chapter_01과 완전히 별개인 독립 레벨 후보**다. `LevelCollection`은 특정 챕터의 진행 순서와 관계없이 쓸 만한 레벨을 모아 비교·수정·보관하는 개발용 씬이다.
- 사용자 근거: 2026-10-18 A·B·C 비교 제작 요청, 2026-10-19 플레이 피드백·보관 씬 통합 요청과 Chapter_01에서 별개로 남겨 달라는 후속 정정이다.
- 이 기록의 A·B는 보관 씬의 `Level_A`·`Level_B`다. Chapter_01의 과거 전체 진행 설계에서 쓰인 후보명 A와 구분한다.
- 독립 레벨 목록·해법·재사용 설명은 [레벨 보관소](../levels/README.md), 사용법과 에셋 위치는 [레벨 보관 씬](../guides/ROOM_AUTHORING.md#레벨-보관-씬), 공통 기획 원문은 [Notion 안내](../notion/NOTION_GUIDE.md)를 따른다. 이 기록은 사용자 결정과 미확정 범위를 보존하며 현재 Editor 상태·수치·기획 원문을 대신하지 않는다.

## 유지할 결정

- A·B의 제작 승인·평가·보관 결정은 이 문서에서 관리한다. Chapter_01의 도입·중반·후반으로 편입하거나 챕터 완성 범위에 포함하지 않는다.
- A는 문·CASTLING을 익힌 뒤, B는 상자를 경험한 뒤 사용할 만하다는 사용자 평가를 보존한다. 이는 각 레벨이 전제하는 학습 경험에 대한 평가다. 적용할 챕터와 실제 등장 순서는 별도로 정한다.
- 두 레벨은 `_Development/LevelCollection` 안에서 독립적으로 편집·플레이할 수 있게 보존한다. A 다음 B로 이어지는 진행이나 자동 전환을 추가하지 않는다.
- 캐릭터·장치·메뉴·글꼴·편집 도구 같은 공용 재료는 재사용한다. 레벨 보관과 공용 재료 사용으로 챕터 귀속을 확정하지 않는다.

## 제작·피드백 이력

### 2026-10-18 A·B·C 비교 제작 승인

- 사용자는 세 공간안을 나중에 선택하거나 수정할 수 있도록 모두 제작하고, A·B·C를 각각 서브 에이전트에 맡기도록 명시 요청했다. 앞선 설계 전용 범위는 이 세 시안의 비교 제작에 한해 대체한다.
- A는 두 갈래의 판·문과 CASTLING 인계, B는 상부 물체 공급과 공동 도약면, C는 방향을 바꾸며 내려가는 협곡으로 각각 편집 가능한 별도 씬에 제작한다. 세 안을 하나의 긴 레벨로 이어 붙이거나 최종안을 자동 채택하지 않는다.
- 기존 Chapter_01과 사용자 편집은 보존하며, 캐릭터·물리·현재 CASTLING 홀드/안전 판정·공유 카메라 기본 최소8은 시안에 맞춰 임의 변경하지 않는다. 기존 미승인 v3의 동시 판·고정 개방·완료 UI를 새 시안의 공통 규칙으로 채택하지 않는다.
- 당시에는 게임 처음 부분을 검토할 세 비교안으로 제작했으며, 후속 플레이 평가와 2026-10-19 분리 요청에 따라 현재 A/B는 특정 챕터에 배정하지 않은 독립 후보로 보존한다. 최종 챕터 분량·완료·능력 해금·새 조작 규칙은 확정하지 않는다. 실제 입력 도달성과 대안·실패·복구, 카메라 정보 시점을 검증하고 결과를 비교 자료로 남긴다. 커밋·push·PR·이슈 수정은 이번 요청에 포함하지 않는다.

### 2026-10-19 A·B·C 비교 플레이 피드백

- 사용자는 A를 상당히 좋게 평가했다. 다만 CASTLING과 문에 대한 학습을 전제로 하므로 게임 맨 처음보다 두 기믹을 경험한 뒤 나오는 응용 구간 후보로 보존한다. 구체적인 배치 순서나 최종 채택은 아직 확정하지 않았다.
- A 끝부분 계단형 플랫폼 사이 틈은 캐릭터 몸체 폭보다 좁아 떨어지지 않는다는 사용자 플레이 관측이 있다. 이 틈을 점프 필수 구간이나 낙하 위협으로 평가하지 않는다. 수정 요청·실제 치수 재측정 없이 틈을 넓히거나 물리 수치를 바꾸지 않는다.
- 사용자는 B를 나쁘지 않게 평가했으나 게임 첫 구간이나 상자를 처음 소개하는 레벨로는 부적절하다고 판단했다. 상자를 먼저 경험한 뒤 한 번 정도 나오는 응용 구간 후보로 보존한다. 상자 최초 소개 방식과 실제 등장 순서는 미확정이다.
- 사용자는 C를 부정적으로 평가했다. 위협이나 의미 있는 판단 없이 꼬불꼬불한 길을 이동하는 경험에 가깝다는 피드백이다. 현재 C를 첫 구간의 유효한 후보나 협동 경험으로 추천하지 않는다. 위험 장치 추가 등 재제작은 확정하지 않았다. 개별 씬 정리는 아래의 후속 보관 씬 통합 요청을 따른다.
- 이번 비교에서 A/B의 긍정 평가는 처음 플레이하는 구간으로서의 적합성 승인이 아니다. 새로운 첫 구간을 설계할 때는 플레이어가 아직 배우지 않은 기믹을 전제로 삼지 않고, 실제로 발생하는 실패·위험과 판단을 검토한다. 새 도입안 제작은 별도 구체안과 승인이 필요하다.

### 2026-10-19 레벨 보관 씬 통합

- 사용자는 쓸 만한 레벨을 모을 씬 하나를 만들고 A/B를 넣은 뒤 개별 시안 씬 파일을 정리하도록 요청했다. 후속으로 `_Development` 폴더 안에 두도록 지정했다.
- A/B는 각각 독립적으로 편집·플레이하는 응용 구간으로 보존한다. 둘을 첫 챕터의 진행 순서로 연결하거나 첫 학습 구간으로 채택한 것은 아니다. C는 통합 대상에서 제외한다.
- 통합 씬의 자기 외곽선·참조와 A/B 실제 입력을 확인한 뒤 개별 A/B/C 시안 씬·전용 외곽선·대응 메타를 정리한다. 원래 Chapter_01과 사용자 튜닝은 유지한다. A 후반 틈에 대한 피드백은 이번 파일 정리로 임의 수정하지 않는다.
- 활성 레벨 루트만 켜는 편집 절차를 사용하며 새 게임 UI·능력·장치·진행 규칙을 추가하지 않는다. 사용 방법과 현재 에셋 위치는 [룸 만들기](../guides/ROOM_AUTHORING.md#레벨-보관-씬)에 둔다.

### 2026-10-19 독립 레벨 보관소 문서화

- 사용자는 이후에도 좋은 독립 레벨 아이디어가 계속 쌓일 수 있도록 문서의 연결을 확장 가능하게 만들고, 기존 보관 씬과 연결된 보관소에서 해법 등을 확인할 수 있게 요청했다.
- 보존할 아이디어·해법·대안·실패·복구와 확인 범위를 레벨별로 찾을 수 있게 남긴다. 실제로 통과한 경로와 설계 가설, 사용자 평가와 챕터 편입 결정을 구분한다. A/B를 Chapter_01과 별개로 보존하는 결정은 유지한다.
- 공통 보관 정책과 새 독립 레벨의 짧은 제작 승인·평가·보관 또는 편입 결정은 관련 ID와 범위를 붙여 이 기록에 남긴다. 개별 이력이 길어지면 해당 ID의 별도 제작 결정 기록을 연결한다. 레벨 목록·현재 해법·위치는 보관소와 카드에서 갱신한다.

## 미확정 범위와 다음 작업

- A·B의 최종 채택, 사용할 챕터, 등장 순서, 연결할 앞뒤 레벨, 추가 수정은 미확정이다. 실제 챕터에 배치할 때는 해당 흐름을 설계하고 사용자 승인을 받는다.
- 독립 레벨·보관 씬의 제작·수정·평가 전에는 보관소의 해당 카드와 이 기록·사용 안내를 읽는다. Chapter_01 작업은 [해당 챕터 기록](CHAPTER_01.md)을 사용하며, A·B 평가를 그 챕터의 구성 결정으로 적용하지 않는다.
- 실제 타일·카메라·시작점·장치 참조와 검증 상태는 현재 씬·코드에서 확인한다. 새 사용자 평가나 편입 결정이 생기면 관련 범위만 갱신한다. 일회성 측정·화면 자료는 [.work 안내](../../.work/README.md)에 따라 필요한 동안만 보존한다.
