# 이동식 발판 레벨 실험 종료 기록

## 범위와 근거

- 관련 기능: 밀어서 옮기는 발판과 두 압력판·문을 활용한 독립 프로토타입 `Dev_MovableStep`.
- 출처: 2026-10-16 이 대화의 설계 승인·제작 요청·사용자 검토. 사용자는 상자 감각과 레벨에 대해 제한적으로 긍정 평가했고, 이번 테스트 종료와 로컬 기록만 유지를 선택했다.
- 기획 원문: [CASTLING 기획서](https://app.notion.com/p/3dcb3e6e776c81f08abde9fa6cefdb80). 기능과 재사용 방법은 [발판 안내](../guides/PUSHABLE_PLATFORM.md), 구현 범위와 앞선 기능 검증은 [이슈 #19](https://github.com/nelu572/CASTLING/issues/19)에 연결한다.

## 유지할 결정

- 이번 실험의 제작·테스트는 종료한다. 씬·발판 코드·프리팹·압력판/문 통합은 보존한다. 추가 테스트나 개선을 계속 대기하는 상태로 두지 않는다.
- 사용자 평가: “상자의 감각 자체는 나쁘지 않은데”, “레벨 자체는 나쁘진 않아보여”. 이를 완성된 레벨이나 재미의 전면 승인으로 확대하지 않는다.
- 일반 이동으로 밀기·탑승하고, 발판으로 압력판을 누르며, 같은 물체를 다른 활동면에 재사용하는 방식은 이 프로토타입에서 작동했다. 특정 레벨 구조나 발판 사용을 이후 레벨의 공식으로 강제하지 않는다.
- 공유 카메라는 기본 최소 직교 크기 8을 기준으로 설계하며 특수한 좁은 구역만 예외로 한다. 적용 방법은 [룸 안내](../guides/ROOM_AUTHORING.md#카메라가-보여주는-범위)를 따른다.

## 종료 시 확인 범위와 미확정 범위

- 저장된 Entry부터 두 캐릭터 Goal까지 실제 PlayerInput으로 29단계·8조건의 연속 경로를 통과했다. 연속 완주 중 위치·속도를 직접 쓰지 않았다. 좌우 밀기·탑승·발판 압력판 반응·CASTLING 후 발판 위치 유지·룩 충돌 종료·문 점유/해제·복구는 별도 시작 조건의 국소 검사와 구분했다.
- 기존 캐릭터/판/문 회귀 검사는 Chapter_01 복제본의 임시 바닥·공허 비활성 조건에서 격리했다. 현재 챕터 전체 경로나 완주를 검증한 결과는 아니다. 사용자 원본 씬·외곽선·TimeManager·Dev_Gameplay는 보존했다.
- 카메라 최소값을 4.5에서 8로 조정한 뒤에는 실제 출력 크기8·화면비2:1의 시작 Game View만 재확인했다. 최종 카메라로 전체 경로의 화면을 재검증한 것은 아니다.
- 커밋 정리 때 사용자가 추가한 외곽선의 미저장 변경을 확인했고, 사용자 요청으로 씬과 대응 `.platformoutlines` 에셋을 저장·포함했다. 저장된 외곽선 참조를 확인했으며 실험 종료 후 Play 테스트는 추가하지 않았다.
- 기술 통과와 사용자 인상 외에 처음 플레이하는 두 사람의 발견성·체감 난이도·재미·출시 아트는 확정하지 않는다. 발판 운반이 의미 있는 협의인지 반복 운반과 대기인지도 별도 평가 대상이다.
- 기존 공허 복귀의 발판 초기화는 추가하지 않았다. 문을 발판으로 받치는 대안 풀이와 밀집 배치의 겹침 버퍼 한계는 후속 사용 시 확인한다.

## 다음 작업에서 사용하는 방법

- 이 발판을 재사용하거나 실험을 비교할 때 읽는다. 실제 배치·물리·카메라·참조 값은 현재 Editor와 코드에서 다시 확인하며 이 기록으로 사용자 튜닝을 되돌리지 않는다.
- 일회성 설계안·입력 계획·raw 결과·스크린샷은 사용자 검토 종료에 따라 정리한다. 필요한 종료 결정은 이 기록과 사용 안내에 남긴다.
- 사용자가 후속 실험·수정을 요청하거나 기획·기믹이 바뀌면 해당 범위에서 결정을 갱신한다. 이번 종료를 근거로 새 제작을 자동 시작하지 않는다.
- GitHub 종료 보고는 게시하지 않고 로컬 기록만 유지한다. PR 게시와 이슈 #19의 상태 변경은 별도 요청 없이 수행하지 않는다.
