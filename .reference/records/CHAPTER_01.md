# Chapter_01 제작 결정 기록

2026-10-02~05 작업에서 사용자가 정한 동작과 아직 미확정인 범위를 보존한다. 당시 좌표·색·물리·카메라 수치와 중간 제작·검증 통계는 보존하지 않는다. 현재 상태는 Unity Editor·코드·Notion에서 확인하고, 이 기록에 맞춰 사용자 튜닝을 되돌리지 않는다.

기준 원문은 [Notion 기획서](https://app.notion.com/p/3dcb3e6e776c81f08abde9fa6cefdb80)와 [아트 레퍼런스](https://app.notion.com/p/3dcb3e6e776c81f2bb63c68f908c5ec5)다. 아래 내용은 당시 Chapter_01 프로토타입에서 사용자가 지정한 선택이며, 다른 챕터나 미확정 기획의 공통 규칙으로 확대하지 않는다.

## 조작과 장치

| 대상 | 당시 합의 |
| --- | --- |
| 킹 | A/D 이동, W 점프 |
| 룩 | 좌/우 이동, 위 방향키 점프 |
| CASTLING | F로 현재 위치 교환. 거리·시야·공중 사용·재사용 제한 없음. 각자의 속도 유지 |
| 룩 직선 이동 | 오른쪽 Shift + 좌/우, 걷기 속도 2배, 이동 중 방향 고정. 앞쪽 지형 충돌 또는 Shift 해제로 종료 |
| 압력 스위치 | 어느 한쪽을 밟는 동안 문 열림. 문 안에 몸체가 있으면 빠져나간 뒤 닫힘 |
| 공허 낙사 | 한 명이 공허 판정에 닿으면 둘 다 룩 이동 구간 앞의 안전한 평지에서 재시작 |

룩은 Shift와 방향키를 어느 순서로 눌러도 발동한다. 지형에 막힌 뒤에는 Shift를 놓고 다시 눌러야 한다.

재시작은 동시 추락에도 한 번만 실행한다. 암전 중 입력·물리를 정지하고 복귀 뒤 복원하며, 중단 시에도 조작 정지가 남지 않게 한다. 재시작용 RoomEntry와 기존 최초 Starting Entry는 구분한다.

## 제작 범위와 풀이 의도

[Chapter_01 씬](../../Assets/Scenes/Chapter_01.unity)은 하나의 `RoomArea` 안에서 연결된 지형을 걸어서 진행하는 프로토타입이다. 구간마다 암전하거나 시작점으로 이동하지 않는다.

- 첫 낮은 통로는 작은 룩이 통과하고 바닥에서 F로 킹을 넘겨준 뒤 재합류한다. 첫 통로에 점프·룩 직선 이동·공중 F 타이밍을 요구하지 않는다. 이른 F도 다시 F로 복구할 수 있으며 이를 막는 새 제한을 추가하지 않는다.
- 통로 이후 홈으로 내려가 일반 점프로 단차를 오른다.
- 스위치는 밟는 동안 유지되는 장치다. 역할을 넘길 수 있지만 이 장치에서 F 사용 자체가 필수는 아니다. 조기 해제 시 돌아올 수 있게 한다.
- 후속 룩 이동은 직선 이동 뒤 착지한 바닥에서 F로 교환하고 재합류하는 흐름이다. 공중 교환 타이밍을 요구하지 않는다.
- 긴 홈의 앞쪽은 하부 복귀 발판으로 돌아오며, 후반의 바닥 없는 공허에서는 둘 다 재시작한다.

제작 범위는 첫 통로·스위치·룩 이동·공허 추락까지다. 완료 판정은 없다. 챕터 전체의 최종 퍼즐·분량·아트와 두 사람이 처음 플레이할 때의 발견성·체감 난이도는 미확정이다. 스프링·이동 플랫폼은 이 작업에 추가하지 않았다.

## 배경에서 보존할 결정

- Notion 내부 아트 보드는 화면 인상과 구성 방향을 참고하는 자료이며 최종 아트 확정본이 아니다. 이전 생성 시안이 기획 원문을 대신하지 않는다.
- 배경도 독립된 검정·흰색 플랫폼을 사용한다. 베이지·청회색 기운을 넣지 않으며 실제 플레이 플랫폼의 기존 아이보리는 이 작업에서 바꾸지 않았다.
- Near·Mid·Far는 같은 두꺼운 플랫폼 세계의 거리 차이다. Mid를 얇은 받침 건축물로 바꾸지 않고 Far는 먼 곳까지 넓게 이어지는 세계로 보이게 한다.
- 기존 Tilemap·모듈형 Sprite·Neutral Tile과 셀별 색을 사용한다. SkyTone도 기존 Sprite로 표현한다. 새 이미지·머티리얼·셰이더·게임 기믹은 추가하지 않았다.
- 배경 킹·룩 구조물은 사용자 요청으로 `Structures_Far/Visual` 아래에 비활성 상태로 보존한다. 보드에 있다는 이유로 표시를 복구하거나 에셋을 삭제하지 않는다.
- 실제 착지면·홈·문·캐릭터를 먼저 읽을 수 있어야 한다. 이동·확대 중 가림과 거리층의 연속성도 확인한다. 특정 명도·패럴랙스·배치 수치는 공통 규칙으로 고정하지 않는다.

반복해서 필요한 에셋 사용법은 [배경 구조물 조립](../guides/BG_STRUCTURE_MODULAR.md)과 [플랫폼 타일 사용법](../guides/PLATFORM_SHEETS.md), 계층·참조 규칙은 [Unity 하네스](../../.codex/harness/UNITY.md)를 따른다.

## 과거 검증의 범위

당시 실제 PlayerInput으로 연속 경로, 스위치 해제·문 안 몸체 보호, 하부 복귀, 단독 점프 우회와 낙사·재시작을 검사했다. 카메라·배경은 위치를 배치한 구도 검사도 별도로 수행했다. 구도 검사는 실제 입력에 의한 완주와 구분하며, 모든 위치 조합의 안전이나 최종 아트·난이도를 증명하지 않는다.

마지막 배경 작업의 확인 결과를 이전 입력 검사와 합쳐 최종 상태를 전부 재검증했다고 보고하지 않는다. 당시 독립 빌드의 창·전체화면 검사는 수행하지 않았다. 현재 변경은 [Unity 변경 검증](../../.codex/skills/UNITY_VERIFY.md)에 따라 관련 항목을 다시 확인한다.

당시 작업의 캡처·일회성 JSON·검사 코드와 중간 제작 기록은 정리했고, 이후에도 필요한 발견은 해당 지침과 작업 절차에 반영했다. 앞으로 생성하는 자료의 저장·보존·정리 시점은 [.work 안내](../../.work/README.md)를 따른다.
