# Chapter_01 제작 결정 기록

각 작업에서 사용자가 정한 동작과 아직 미확정인 범위를 보존한다. 당시 좌표·색·물리·카메라 수치와 중간 제작·검증 통계는 보존하지 않는다. 같은 항목은 뒤의 승인 결정이 앞선 시안에 우선한다. 현재 상태는 Unity Editor·코드·Notion에서 확인하고, 이 기록에 맞춰 사용자 튜닝을 되돌리지 않는다.

기준 원문은 [Notion 기획서](https://app.notion.com/p/3dcb3e6e776c81f08abde9fa6cefdb80)와 [아트 레퍼런스](https://app.notion.com/p/3dcb3e6e776c81f2bb63c68f908c5ec5)다. 아래 내용은 당시 Chapter_01 프로토타입에서 사용자가 지정한 선택이며, 다른 챕터나 미확정 기획의 공통 규칙으로 확대하지 않는다.

독립 레벨 A·B의 목록·해법은 [레벨 보관소](../levels/README.md), 제작·평가·보관 결정은 [별도 기록](LEVEL_COLLECTION.md)에서 관리한다. A·B는 Chapter_01과 별개이며 이 챕터의 진행 구성에 포함하지 않는다.

## 현재 작업 기준 · 2026-10-19 정리

- 사용자는 마지막 구간을 직접 조금 수정한 뒤, **Chapter_01의 완료가 아니라 현재와 같은 방향으로 이후 레벨을 이어갈 상태**라고 정리했다. 현재 끝면을 챕터 종료로 확정하거나 완료 판정·다음 챕터·전체 분량·룸 수·능력 해금을 임의 추가하지 않는다. 이슈 #4의 전체 목표가 끝났다는 뜻도 아니다.
- 지금까지 승인한 흐름은 평지와 짧은/긴 일반 점프 → 룩을 밟아 올라가는 킹과 룩만 지나는 낮은 통로 → 재합류와 추가 점프 → 룩 대쉬 → 받침으로 준비한 높은 위치와 CASTLING의 응용이다. 다음 구간의 구체 구조는 새 도면을 먼저 검토받는다. 마지막 사용자 편집은 현재 씬을 기준으로 삼고 과거 도면·타일·입력 계획으로 되돌리지 않는다.
- 도입부 천장은 사용자 요청으로 새 시작 구간까지 연결했다. 지형·천장의 후속 조형은 사용자가 맡으며, 작업자의 시각 마감은 간단한 흑백 면과 작은 모서리 라운드 범위다.
- CASTLING은 현재 짧은 F 홀드·안전 판정·성공/실패 표현을 사용한다. 아래 초기 이력의 즉시 교환·초기 통로·스위치 순서를 현행 설계로 읽지 않는다. 룩 대쉬를 CASTLING보다 먼저 소개하고 튜토리얼 패널·키 표시는 이후에 다룬다는 후속 결정을 유지한다.
- 공유 카메라는 기본 최소8·기존 최대14.5를 유지한다. 새 도입의 시작점·좌측 경계·배경 확장은 승인 범위이며, 과거 최초 Entry 좌표를 복원할 근거가 아니다. 새 체크포인트는 이번 도입에 추가하지 않아 낙사 시 도입을 다시 지나는 비용이 있다.
- 리스폰 뒤 카메라가 이전 확대 크기의 경계 캐시를 쓰던 문제는 [이슈 #20 수정·검증 기록](https://github.com/nelu572/CASTLING/issues/20#issuecomment-6261820978)에 남겼다. 공용 이동·입력 수치를 레벨에 맞춰 변경하지 않는다.

### 다음 작업에서 다시 확인할 사항

- 마지막 사용자 편집 뒤의 전체 경로는 아직 새로 완주 검증하지 않았다. 기존 구간의 실제 입력 통과·점프·복귀 결과를 최신 상태 전체의 검증으로 합산하지 않는다. 재개할 때 현재 지형·충돌·능력·카메라를 확인하고 영향을 받는 경로를 다시 검사한다.
- 후반에서 킹이 높은 자리를 준비한 뒤의 대기, 아래 복구 바닥을 읽는 시점, 룩 선행·CASTLING 운송 대안의 번거로움과 협동 기여는 두 사람이 플레이하며 검토한다. 대안이 있다는 사실만으로 차단하지 않고 더 편한 진행과 비교한다.
- 멀리 벌어진 두 캐릭터의 최대 줌 한계, 튜토리얼 시점·표현, 체크포인트 필요성, 이후 구간과 최종 챕터 분량·마무리 방식은 미확정이다. 이번 정리로 새 규칙이나 최종 재미·난이도를 승인한 것은 아니다.
- Play 중 재컴파일 뒤 발먼지 풀 참조가 유실되는 [기존 이슈 #11](https://github.com/nelu572/CASTLING/issues/11)은 이번 정리의 수정 대상이 아니다. 후반 검사에서도 같은 예외가 관측됐지만 발생 계기는 확정하지 못했으며, 새 Play의 정상 관측을 결함 해결로 해석하지 않는다. 코드 편집·재검사는 [입력 검사 안내](../guides/PLAYTEST_AUTOMATION.md)의 Stop 후 재컴파일 절차를 따른다.
- 완료된 도입·곡선·후반 아트·능력 구간·천장 작업의 일회성 도면·캡처·입력 raw·백업은 이번 사용자 정리 요청에 따라 정리한다. 재사용할 에셋·사용법·독립 A/B와 아래 제작 결정은 보존한다. 이전 미해결 원본·미채택 발상은 해당 작업 안내의 보존 조건을 유지한다.

## 초기 프로토타입 이력 · 후속 결정 전

이 절의 조작·재시작 위치·통로 구성은 초기 제작 당시 합의다. 현행 동작과 제작 범위는 위의 현재 작업 기준과 아래 후속 승인에 따른다.

### 조작과 장치

| 대상 | 당시 합의 |
| --- | --- |
| 킹 | A/D 이동, W 점프 |
| 룩 | 좌/우 이동, 위 방향키 점프 |
| CASTLING | F로 현재 위치 교환. 거리·시야·공중 사용·재사용 제한 없음. 각자의 속도 유지 |
| 룩 직선 이동 | 오른쪽 Shift + 좌/우, 걷기 속도 2배, 이동 중 방향 고정. 앞쪽 지형 충돌 또는 Shift 해제로 종료 |
| 압력 스위치 | 어느 한쪽을 밟는 동안 문 열림. 문 안에 몸체가 있으면 빠져나간 뒤 닫힘 |
| 공허 낙사 | 한 명이 공허 판정에 닿으면 둘 다 룩 이동 구간 앞의 안전한 평지에서 재시작 |

룩은 Shift와 방향키를 어느 순서로 눌러도 발동한다. 지형에 막힌 뒤에는 Shift를 놓고 다시 눌러야 한다.

재시작은 동시 추락에도 한 번만 실행한다. 암전 중 입력·물리를 정지하고 복귀 뒤 복원하며, 중단 시에도 조작 정지가 남지 않게 한다. 재시작용 RoomEntry와 기존 최초 Starting Entry는 구분한다.

### 당시 제작 범위와 풀이 의도

[Chapter_01 씬](../../Assets/Scenes/Chapter_01.unity)은 하나의 `RoomArea` 안에서 연결된 지형을 걸어서 진행하는 프로토타입이다. 구간마다 암전하거나 시작점으로 이동하지 않는다.

- 첫 낮은 통로는 작은 룩이 통과하고 바닥에서 F로 킹을 넘겨준 뒤 재합류한다. 첫 통로에 점프·룩 직선 이동·공중 F 타이밍을 요구하지 않는다. 이른 F도 다시 F로 복구할 수 있으며 이를 막는 새 제한을 추가하지 않는다.
- 통로 이후 홈으로 내려가 일반 점프로 단차를 오른다.
- 스위치는 밟는 동안 유지되는 장치다. 역할을 넘길 수 있지만 이 장치에서 F 사용 자체가 필수는 아니다. 조기 해제 시 돌아올 수 있게 한다.
- 후속 룩 이동은 직선 이동 뒤 착지한 바닥에서 F로 교환하고 재합류하는 흐름이다. 공중 교환 타이밍을 요구하지 않는다.
- 긴 홈의 앞쪽은 하부 복귀 발판으로 돌아오며, 후반의 바닥 없는 공허에서는 둘 다 재시작한다.

제작 범위는 첫 통로·스위치·룩 이동·공허 추락까지다. 완료 판정은 없다. 챕터 전체의 최종 퍼즐·분량·아트와 두 사람이 처음 플레이할 때의 발견성·체감 난이도는 미확정이다. 스프링·이동 플랫폼은 이 작업에 추가하지 않았다.

## 배경에서 보존할 결정

- Notion 내부 아트 보드는 화면 인상과 구성 방향을 참고하는 자료이며 최종 아트 확정본이 아니다. 이전 생성 시안이 기획 원문을 대신하지 않는다.
- 배경도 독립된 검정·흰색 플랫폼을 사용한다. 베이지·청회색 기운을 넣지 않으며 실제 플레이 플랫폼의 기존 아이보리는 이 작업에서 바꾸지 않았다.
- Near·Mid·Far는 같은 두꺼운 플랫폼 세계의 거리 차이다. Mid를 얇은 받침 건축물로 바꾸지 않고 Far는 먼 곳까지 넓게 이어지는 세계로 보이게 한다.
- 당시에는 기존 Tilemap·모듈형 Sprite·Neutral Tile과 셀별 색을 사용했고, SkyTone도 기존 Sprite로 표현했다. 새 이미지·머티리얼·셰이더·게임 기믹은 추가하지 않았다.
- 배경 킹·룩 구조물은 사용자 요청으로 `Structures_Far/Visual` 아래에 비활성 상태로 보존한다. 보드에 있다는 이유로 표시를 복구하거나 에셋을 삭제하지 않는다.
- 실제 착지면·홈·문·캐릭터를 먼저 읽을 수 있어야 한다. 이동·확대 중 가림과 거리층의 연속성도 확인한다. 특정 명도·패럴랙스·배치 수치는 공통 규칙으로 고정하지 않는다.

반복해서 필요한 에셋 사용법은 [배경 구조물 조립](../guides/BG_STRUCTURE_MODULAR.md)과 [플랫폼 타일 사용법](../guides/PLATFORM_SHEETS.md), 계층·참조 규칙은 [Unity 하네스](../../.codex/harness/UNITY.md)를 따른다.

### 2026-10-08 배경 기본색 편집 결정

- 배경 기본색은 원하는 색을 담은 새 단색 채움 PNG·Tile로 만들고, 기존 `BaseColor` 타일맵에서 칠한다. 팔레트의 그림 색이 실제 기본색이 되도록 한다.
- 그라데이션은 기본 색조를 유지하며 명도를 변화시키는 별도 효과로 다룬다. 단색 타일 전환 이후 사용자 요청으로 별도 흑백 알파 Sprite를 추가했으며, 위쪽은 밝고 아래쪽은 어둡게 표현한다. 강도와 범위는 Inspector에서 조절한다.

## 2026-10-09 초반 튜토리얼 변경 결정

- 이 대화에서 사용자는 기본 점프도 계단을 오르는 구성 대신 플랫폼 사이 틈을 건너도록 요청했고, 기본 점프·룩 점프에 실제 낙사 구간을 두는 시안을 승인했다. 이 초반 흐름은 위의 이전 첫 통로·홈 구성에 우선한다.
- 초반은 플랫폼 사이 틈을 기본 점프로 건넌 뒤, 룩의 가속 점프와 착지 후 F 교환·재합류로 이어진다. 사용자는 일자로 늘어선 평범한 배치를 수정하고 안내 텍스트를 빼도록 요청했다. 높낮이와 발판 형태를 달리하며, 실제 틈 폭과 지형 좌표는 씬에서 확인한다.
- 시작 발판은 사용자가 애벌레처럼 보인다고 지적한 검정·아이보리 반복 줄무늬를 없애고 한 색으로 이어지는 형태로 정리한다.
- 룩은 오른쪽 Shift 직선 이동 중 위 방향키를 누르면 지면에서 점프하며, 그 이동의 수평 속도를 착지까지 유지한다. Shift를 놓아도 이미 시작한 점프는 이어진다. 일반 점프·중력 수치를 따로 변경하는 요청은 없었다.
- 튜토리얼의 낙사는 최초 시작 위치에서 둘이 다시 출발한다. 튜토리얼 전용 판정의 RoomEntry 참조로 구현하며 기존 후속 공허 판정과 최초 StartingEntry를 다른 장치로 바꾸지 않는다.
- 정확한 난이도와 첫 플레이의 발견성은 실제 플레이로 계속 검토한다. 기존 비활성 배경을 이 결정으로 자동 활성화하거나 색·물리·카메라 튜닝을 원복하지 않는다.

## 2026-10-14 카메라 시안 검토

- 사용자는 다각형 경계를 유지하면서 시작 구간의 기본 구도와 줌을 먼저 잡아 보는 시안을 승인했다.
- 검토 뒤 사용자는 계속 큰 줌, 복귀 정지, 킹이 화면 밖으로 사라지는 동작을 지적하고 고정 구도 방식을 거절했다. 이 시안을 최종 카메라 방식으로 사용하지 않는다.
- 사용자는 피코파크를 참고해 기획했다고 설명하고, 두 명이 같은 퍼즐을 읽는 공유 화면·거리별 줌·카메라 경계 여유를 시작 구간에서 적용해 보는 방향을 승인했다. 가까우면 좁게, 떨어지면 필요한 만큼 넓게, 재합류하면 위치와 줌이 복귀하도록 한다.
- 현재 적용은 시작 구간의 대기·도착·교환 구도 시안이다. 챕터 전체의 퍼즐 규모와 큰 분리 거리 처리, 최종 구도·줌은 미확정이다. 플레이어의 이동·CASTLING 거리 제한을 임의로 추가하지 않는다.
- 이후 사용자는 카메라 경계를 사각형만 편집할 수 있도록 단순화하는 방향을 승인했다. `BoxCollider2D` 경계와 두 명 추적·거리별 줌을 사용하며, 다각형 경계 시안은 대체한다.

## 2026-10-17 CASTLING 안전 동작과 실패 피드백

### 후속 시각 마감

- 사용자는 현재 구성을 첫 구간으로 긍정 평가하고, 곡선 타일 등으로 조금 다듬도록 요청했다. 기존 동선·협동 분기·점프 틈을 유지하며 기존 곡선 타일로 모서리와 큰 덩어리의 끝을 마감한다. 새 지형 흐름·장치·아트 원본·능력·물리·카메라 변경으로 확대하지 않는다.
- 사용자가 앞부분의 흑백 곡선 색 경계와 모서리를 직접 다듬은 뒤 뒷부분 아트를 맡겼다. 사용자 앞부분·상부 편집을 보존하고, 같은 기존 혼합 타일로 후반 큰 바닥과 마지막 발판의 흑백 경계를 크기·방향을 달리해 이어간다. 색 배분의 변경이며 새 동선·장치를 추가하는 요청이 아니다.
- 후속 정정: 사용자는 조형·아트 형태는 직접 만들겠다고 했다. 이후 작업자의 시각 마감은 **간단한 흑백 구분과 작은 모서리 라운드**까지만 한다. 큰 곡선 색 경계·장식적 모양을 임의로 구성하지 않는다. 이번 능력 확장부에 작업자가 추가한 내부 곡선 패턴은 단순 색면으로 정리하고, 사용자 기존 앞부분·상부 아트와 플레이 구조는 보존한다.

### 같은 날 후반 능력 도입 요청

- 사용자는 기존 첫 구간 뒤에 룩 대쉬와 CASTLING을 쓸 수 있는 후반을 검토하도록 요청했다. 구체 공간도·대안·복구를 먼저 제시하고 제작 승인 뒤 반영한다. 현재 추가 설계는 전체 챕터 길이·종료·룸 수의 확정이 아니다.
- 특수 능력 첫 사용 지점의 작은 키 표시 제안에 대해, 사용자는 튜토리얼 패널을 나중에 만들 예정이며 지금은 넣지 말라고 답했다. 이번 후반 작업에는 패널·키 표시를 추가하지 않는다.
- 후속 정정: 이번 추가 구간은 **룩 대쉬를 먼저, CASTLING을 그 뒤**에 배치한다. 킹의 상부 진입은 혼자 하는 점프가 아니라 **룩을 받침으로 삼아 올라가는 협력**이며, 이후 킹은 위쪽 발판, 룩은 스킬 경로를 이용한다. 낮은 통로를 통과하고 교환하는 방식은 단조롭다는 피드백으로 CASTLING 공간을 재설계한다. 이 순서 정정은 구체 지형·치수의 제작 승인과 구분한다.
- 사용자는 양끝 발코니·중앙 합류의 v2 지형도를 검토한 뒤 `ㄱㄱ`로 제작을 승인했다. 대쉬를 먼저 경험하고, 룩을 밟아 킹이 높은 왼쪽 출발점을 확보하고, 룩은 아래 대쉬와 바깥 계단으로 오른쪽 출발점을 확보한다. CASTLING 뒤에는 룩이 긴 틈을 대쉬하고 킹이 짧은 틈을 점프하여 중앙 연결면에 합류한다. 같은 구조 안의 실제 입력 여유·복귀·우회 비교와 타일 마감, 카메라 경계/배경 연장을 포함하며 물리·입력·줌·새 장치 변경은 포함하지 않는다.

### 같은 날 첫 평지·점프 도입 추가 승인

- 사용자는 맨 처음에 평지를 조금 늘리고 짧은 점프와 긴 점프를 경험하도록 요청했다. 기존 지형 앞에 평지 → 짧은 틈 → 함께 멈출 착지면 → 더 넓은 틈을 붙이는 치수 도면을 검토한 뒤 `ㄱㄱ`로 제작을 승인했다.
- 기존 첫 턱·협동 분기·후반 및 사용자 아트는 보존한다. 시작점을 새 도입부로 옮기고 카메라의 왼쪽 경계와 기존 배경의 적용 범위를 연장한다. 줌 8..14.5, 입력·점프 물리·능력은 유지하며 새 장치·튜토리얼 UI·체크포인트를 추가하지 않는다.
- 두 틈은 고정 높이 점프의 수평 이동 차이를 익히는 구성이다. 제안 폭은 두 캐릭터의 실제 일반 점프와 착지·정지 여유를 측정하여 같은 구조 안에서 조정한다. 특수 능력을 잠가 정해진 풀이를 강제하지 않는다.
- 기존 공동 리스폰을 유지하므로 이후 낙사에도 추가 도입을 다시 지나간다는 비용을 제시한 상태에서 승인받았다. 카메라 경계의 좌측 연장은 극단적으로 멀리 벌어진 두 플레이어의 가시성을 모두 해결한다는 뜻이 아니다.

## 과거 검증의 범위

당시 실제 PlayerInput으로 연속 경로, 스위치 해제·문 안 몸체 보호, 하부 복귀, 단독 점프 우회와 낙사·재시작을 검사했다. 카메라·배경은 위치를 배치한 구도 검사도 별도로 수행했다. 구도 검사는 실제 입력에 의한 완주와 구분하며, 모든 위치 조합의 안전이나 최종 아트·난이도를 증명하지 않는다.

마지막 배경 작업의 확인 결과를 이전 입력 검사와 합쳐 최종 상태를 전부 재검증했다고 보고하지 않는다. 당시 독립 빌드의 창·전체화면 검사는 수행하지 않았다. 현재 변경은 [Unity 변경 검증](../../.codex/skills/UNITY_VERIFY.md)에 따라 관련 항목을 다시 확인한다.

당시 작업의 캡처·일회성 JSON·검사 코드와 중간 제작 기록은 정리했고, 이후에도 필요한 발견은 해당 지침과 작업 절차에 반영했다. 앞으로 생성하는 자료의 저장·보존·정리 시점은 [.work 안내](../../.work/README.md)를 따른다.
