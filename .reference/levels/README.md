# 독립 레벨 보관소

쓸 만한 레벨 아이디어를 모으고, 해법과 평가를 찾아 다시 제작·수정할 때 사용하는 입구다. 아이디어만 있는 항목도 보관할 수 있으며, 제작 여부와 확인한 범위를 함께 적는다. **보관 레벨은 Chapter_01과 별개이고, 사용할 챕터와 등장 순서는 별도 결정한다.**

## 레벨 목록

| ID · 통칭 | 핵심 경험 · 재료 | 선행 경험 | 제작·평가·검증 | 해법과 씬 위치 |
| --- | --- | --- | --- | --- |
| `LV001` · A | 두 갈래에서 길을 열고 CASTLING으로 담당 인계 · 판/문, 낮은 통로 | 문·압력판·CASTLING | 씬 보관 / 사용자 긍정 / 현행 조작으로 기본 경로 재확인 | [인계 회랑](LV001_HANDOFF_CORRIDOR.md) · `LevelCollection / Level_A` |
| `LV002` · B | 위에서 물체를 내려 남은 사람의 길 만들기 · 직접 밟기, 물리 발판 | 상자·물리 발판 | 씬 보관 / 사용자 긍정 / 현행 조작으로 기본 경로 재확인 | [발판을 내려 함께 오르는 안뜰](LV002_RETURN_STEP_COURTYARD.md) · `LevelCollection / Level_B` |

ID는 문서를 찾기 위한 고정 번호다. 챕터 번호·난이도·플레이 순서를 뜻하지 않는다. 기존 통칭 A/B와 씬 루트 이름은 그대로 사용한다. 새 보존 아이디어는 `LV003`부터 추가한다. C는 사용자 평가에 따라 보관 씬에 넣지 않았으며, [평가와 정리 결정](../records/LEVEL_COLLECTION.md#2026-10-19-abc-비교-플레이-피드백)을 참고한다.

## 찾아보는 순서

1. 위 목록에서 핵심 경험과 선행 경험으로 후보를 고른다. 레벨 카드에서 공간 구조·기본 해법·역할 변화·대안·복구·남은 질문을 읽는다.
2. 제작 승인·사용자 평가·채택 범위의 근거는 [독립 레벨 제작 결정 기록](../records/LEVEL_COLLECTION.md)에서 확인한다. 공통 기획은 [Notion 안내](../notion/NOTION_GUIDE.md)를 따른다.
3. 플레이하거나 편집할 때는 [레벨 보관 씬 사용법](../guides/ROOM_AUTHORING.md#레벨-보관-씬)에 따라 [LevelCollection 씬](../../Assets/Scenes/_Development/LevelCollection.unity)을 사용한다. 카드의 씬 경로와 루트로 대상을 찾는다.

문서의 역할은 다음과 같다.

| 자료 | 남기는 내용 |
| --- | --- |
| 이 보관소 목록 | 어떤 레벨이 있고 어디서 찾아볼지, 제작·평가 상태 |
| 레벨별 카드 | 핵심 아이디어, 공간과 해법, 두 사람의 기여, 대안·실패·복구, 재사용 시 주의점 |
| 제작 결정 기록 | 누가 무엇을 승인·평가했는지와 미확정 범위 |
| 씬 사용법 | 루트 선택·편집·저장·참조 관리 절차 |
| `.work` | 일회성 도면·입력 계획·측정·화면 원자료. 보관소를 읽는 데 필수인 해법은 카드에 남긴다. |

## 새 아이디어를 쌓는 방법

1. 보존할 독립 아이디어에 다음 빈 ID를 부여하고 [레벨 카드 양식](../../.templates/LEVEL_LIBRARY_TEMPLATE/template.md)을 이 폴더의 `LV003_설명.md` 같은 이름으로 복사한다. 기존 ID는 이름 변경·보류·정리 뒤에도 재사용하지 않는다.
2. 핵심 경험과 공간 구상을 짧게 쓰고 목록에 한 줄 추가한다. 미제작이면 씬 위치를 `없음`, 해법을 `설계 가설`, 검증을 `미실행`으로 적는다. 보관 등록과 실제 제작 승인은 각각 기록한다.
3. 제작한 뒤 실제 씬 경로·루트·기본 해법을 갱신한다. 성공한 한 경로를 유일한 정답으로 고정하지 않고, 더 직관적인 진행·단독 선행·직접 협력·능력 조합도 후보로 남긴다. 대안이 핵심 협동을 살리는지, 기존 동선을 굳이 선택할 이유가 있는지 평가한다.
4. **제작 상태, 기술·입력 확인, 사용자 경험 평가, 챕터 채택**을 따로 적는다. 입력 완주를 재미·발견성·모든 우회 차단의 확인으로 확대하지 않는다. 공통 보관 정책과 짧은 결정은 독립 레벨 결정 기록에 ID와 함께 남기고 카드에서 연결한다. 한 레벨의 이력이 길어지면 기존 [제작 결정 양식](../../.templates/RECORD_TEMPLATE/template.md)으로 `.reference/records/LV003_설명.md` 같은 별도 기록을 만들고 해당 카드에서 연결한다.
5. 같은 경험의 튜닝은 기존 카드를 갱신한다. 다른 경험으로 갈라지는 안은 새 ID를 만들고 원안과 연결한다. 챕터 편입이 승인되면 양쪽 기록에 사용 범위와 수정 사항을 연결한다.

## 갱신·검증·보존 기준

- 카드의 해법은 확인 시점의 설명이다. 지형·몸체·물리·장치·카메라가 바뀌면 영향을 받는 해법과 복구의 확인 상태를 `재검증 필요`로 바꾸고 실제 씬에서 확인한다. 과거 좌표나 입력 시간을 사용자 튜닝의 복원 기준으로 쓰지 않는다.
- 카드는 씬 미제작·부분 확인·실제 입력 확인·사용자 관측·미검증 가설을 구분한다. 원자료를 정리해도 핵심 해법, 평가 이유와 검증 한계가 남도록 쓴다.
- 현재 A/B의 제작·사용자 평가는 2026-10-19 보관 통합과 플레이 피드백을 기준으로 한다. 2026-10-20 현행 조작으로 현재 보관 씬에서 기본 해법을 실제 입력으로 재확인했으며, 확인 범위와 남은 한계는 각 카드에서 읽는다. 이 재검증으로 챕터 배정·최종 채택이나 새 사용자 경험 평가를 확정하지 않는다.
- 아이디어·레벨을 재사용할 이유가 있는 동안 목록과 카드를 유지한다. 미채택·보류도 이유를 남길 수 있다. 씬을 정리하면 카드의 위치·상태와 참조를 함께 갱신하고, 문서를 없앨 때는 관련 목록·링크를 함께 정리한다.
- 작성 양식과 자료 관리 기준은 [자료 추가 기준](../../.codex/harness/TEMPLATES.md), 일회성 자료의 보존·정리는 [.work 안내](../../.work/README.md)를 따른다.
