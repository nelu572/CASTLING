# 이동식 발판 사용 안내

## 용도와 사용 시점

캐릭터의 일반 이동으로 밀고 위에 설 수 있는 물리 발판을 배치할 때 읽는다. 특정 레벨의 필수 기믹이나 모든 레벨의 제작 공식은 아니다.

- 프리팹: `Assets/Prefabs/Gameplay/PushablePlatform.prefab`
- 식별/설정 검사: `Assets/Scripts/Gameplay/Puzzles/PushablePlatform.cs`
- 압력판/문 통합: `PressurePlateSwitch.cs`, `PressureGate.cs`
- 독립 시험 씬: `Assets/Scenes/_Development/Dev_MovableStep.unity` (Editor 시험용, Build Settings 미등록)
- 관련 작업: [이슈 #19](https://github.com/nelu572/CASTLING/issues/19)

## 배치와 조율

Unity MCP로 프리팹 인스턴스를 해당 룸의 `Puzzles` 아래에 둔다. 기본 구성은 Environment 레이어, Dynamic Rigidbody2D, 비 Trigger BoxCollider2D, 회전 고정이다. 현재 크기·질량·감쇠·마찰은 프리팹/인스턴스 Inspector에서 확인한다. 수치를 과거 제작 기록으로 되돌리지 않는다.

발판 이동은 물리 접촉으로 처리한다. 새 입력이나 캐릭터 이동 수치 변경은 없다. `PlayerMovement`의 기존 Environment 접지와 받침 Rigidbody 수평 속도 반영을 사용한다. 런타임에 지형·참조를 생성해 기본 배치를 대신하지 않는다.

물체 양쪽에 사람이 설 공간을 남긴다. 밀기만 가능하므로 벽에 완전히 붙이면 반대쪽으로 밀기 어려울 수 있다. 정지 지형·접근 경로와 실패 후 복구를 레벨별로 설계한다. 작은 사각 턱도 플레이어를 막을 수 있으며, 경사면이나 다른 접근이 실제 입력으로 가능한지 확인한다.

## 다른 기믹과의 관계

- 발판도 압력판을 누른다. 판은 Player 또는 활성 `PushablePlatform` 몸체만 인정하며 일반 Environment 지형은 제외한다. 판의 발 높이·수직 속도 조건은 기존과 같다.
- 열린 문 안에 캐릭터나 발판이 남아 있으면 충돌체를 복원하지 않는다. 물체를 빼고 판도 비면 닫힌다. 발판으로 문을 받치는 대안이 생기므로 경험에 미치는 영향을 레벨별로 평가한다. 이 안전처리 자체를 숨겨진 필수 풀이로 삼지 않는다.
- 룩 수평 이동은 앞 Environment 접촉으로 종료하므로 발판에 충돌해 멈춘다. 수평 이동으로 계속 미는 능력이 추가된 것은 아니다.
- CASTLING은 캐릭터 위치만 교환하며 발판을 옮기지 않는다. 각 캐릭터의 몸체·속도는 유지되므로 발판 주변 교환의 충돌 여유를 확인한다. 기존 좁은 틈 이슈 #18을 해결한 것으로 취급하지 않는다.
- 기존 공허 복귀는 플레이어만 복원한다. 발판 초기화는 지원하지 않으므로 낙사/리셋을 사용하는 레벨은 물체의 복구를 별도 검토해야 한다. fresh Play/씬 재로드는 저장된 초기 배치로 시작한다.

## 검증과 한계

검사는 [플레이테스트 자동화](PLAYTEST_AUTOMATION.md)와 [Unity 검증](../../.codex/skills/UNITY_VERIFY.md)을 따른다. `Rooms Root` 아래 물체는 `path:`의 `x`/`y`/`velocityX`/`velocityY`로 읽을 수 있다. 발판 변위는 `x` + `relativeToStart`를 사용한다. `deltaX`는 캐릭터 전용이다.

새 씬에서는 양방향 밀기, 탑승자 유지/이동, 점프, 입력 해제 뒤 정지, 벽·문 접촉, 압력판 누름/해제, 잘못 옮긴 뒤 복구를 확인한다. 압력판과 문은 고정 크기 겹침 버퍼를 쓰므로 복잡하게 겹치는 배치에서는 반환 수가 포화되지 않는지도 확인한다.

2026-10-16 독립 씬에서 실제 입력으로 기본 밀기·탑승·발판 압력판 반응·CASTLING 이후 발판 위치 유지·룩 충돌 종료·시작→두 명 목표 경로를 확인했다. 사용자는 상자의 감각과 레벨에 대해 제한적으로 긍정 평가했고 같은 날 이번 실험의 테스트를 종료했다. 이 결과는 처음 플레이하는 두 사람의 발견성·체감 난이도·재미나 다른 배치의 무결성을 보장하지 않는다. 앞선 구현·기능 검증은 [이슈 #19](https://github.com/nelu572/CASTLING/issues/19), 사용자 평가와 종료 결정은 [로컬 종료 기록](../records/MOVABLE_STEP_EXPERIMENT.md)에 남긴다.

후속 레벨은 [룸 카메라 안내](ROOM_AUTHORING.md#카메라가-보여주는-범위)의 기본 최소 직교 크기 8을 기준으로 설계한다. 이 실험에서도 최소값을 8로 조정했으며, 조정 후 재확인한 범위는 시작 Game View다. 같은 물체의 운반·재사용이 의미 있는 협의가 되는지, 반복 운반과 대기로 느껴지는지는 별도로 판단한다.

이 안내와 게임 에셋은 재사용 자료로 보존한다. 동작·프리팹 구조가 바뀌면 함께 갱신하고, 일회성 입력 계획·결과·스크린샷은 `.work`의 검토 종료 조건에 따라 정리한다.
