# Unity 변경 검증

변경 범위에 맞춰 다음을 확인하고, 실행하지 못한 항목은 이유를 남긴다. Unity Editor에서 확인할 항목이 있으면 [Unity 하네스](../harness/UNITY.md)를 읽고 연결된 Editor가 현재 프로젝트와 일치하는지 확인한다.

1. `git diff --check`로 공백 오류를 확인한다.
2. `git status --short`로 의도하지 않은 생성물이 없는지 확인한다.
3. `Assets/`에서 새로 만들거나 이동한 항목은 `.meta` 파일이 함께 있는지 확인한다.
4. C# 변경 후 Unity Editor Console에 컴파일 오류가 없는지 확인한다.
5. 씬·프리팹 변경 후 해당 에셋을 열어 누락된 참조와 컴포넌트 경고를 확인한다.
6. 조작·물리·CASTLING처럼 플레이에 영향을 주는 변경은 관련 개발 씬에서 Play Mode로 확인한다.

## 화면 변경 확인

1. 변경과 관련된 장면을 고르고 프로젝트·씬, Edit/Play Mode, Game View 해상도·화면비, 카메라 상태를 확인한다. 스크린샷에는 실제 Game View의 viewport와 레터박스가 반영되어야 한다.
2. 전후 비교는 같은 위치·해상도·카메라·표시 상태에서 한다. 서로 다른 구도의 이미지는 같은 조건의 비교로 보고하지 않는다.
3. 실제 입력으로 이동한 경로와 구도를 보기 위해 위치를 배치하거나 몸체를 고정한 검사를 구분한다. 구도 캡처만으로 퍼즐 완주나 조작 검증을 통과했다고 쓰지 않는다.
4. 필요한 화면과 확인 결과를 작업 보고에 남긴다. 캡처 방식은 [Unity 하네스](../harness/UNITY.md)를 따르고, 파일은 [.work 안내](../../.work/README.md)에 따라 작업별 폴더에 저장한다. 각 검사 뒤 다음 비교·재검사에 필요 없어진 자료를 정리하고, 검토 완료 응답을 처리할 때 보존 종료 조건을 다시 확인한다. 사용자 검토 대기·문제 미해결 자료는 필요한 동안 유지하며, 남은 자료의 경로·이유·정리 조건을 작업별 안내와 보고에 남긴다.
5. 검사 때문에 변경한 입력 기기·포커스·백그라운드 실행·물리 시뮬레이션·카메라·씬 상태를 확인하고 원래 상태로 복원한다. 검사 전부터 있던 사용자 변경을 되돌리지 않는다.

## 변경별 확인 항목

변경과 관련된 항목만 현재 씬·코드·입력 설정에 맞춰 검사한다. 검사를 통과시키려고 사용자 씬이나 튜닝을 과거 기록의 값으로 되돌리지 않는다.

구체적인 비교·측정·상태 복원은 [재사용 검증 방법](../../.reference/guides/VERIFICATION_CHECKS.md)을 참고한다. 새 검사 방법은 [검사 안내 양식](../../.templates/VERIFICATION_TEMPLATE/template.md)으로 사용 조건과 판정 기준을 작성하고 이 절차에서 연결한다.

- 타일: 같은/다른 Tilemap과 색상 사이의 접합, 대각선 채움·삭제, 곡선의 회전·뒤집기, 부분 접합의 외곽선 유지 여부를 확인한다. 브러시·지우기·Undo/Redo 뒤에도 표시가 갱신되는지 본다.
- 충돌: Sprite Physics Shape와 실제 TilemapCollider2D·CompositeCollider2D 도형이 지형에 맞는지 비교한다. 지형을 변경했다면 Play Mode의 Raycast와 착지로 실제 충돌 높이를 확인한다.
- 카메라: 좌우 경계, 높이 차와 거리 차, 최대 확대에서 두 몸체의 가시성과 카메라 경계 이탈을 확인한다. 의도한 낙사·암전 프레임은 일반 플레이 구도와 구분해 보고한다. 실제 입력으로 이동한 경로와 구도 확인용 배치 검사를 구분한다.
- 진행 경로: 저장된 시작점부터 실제 PlayerInput 조작으로 이동·점프·협동·재합류를 확인한다. 연속 경로 검사 중 위치·속도를 직접 쓰지 않는다. 사례별로 시작 위치만 배치한 안전·복귀·단독 우회 검사와 결과를 구분한다.
- 장치·재시작: 스위치 누름과 점프 해제, 문 안 몸체 보호, 단독·동시 추락 시 중복 없는 재시작, 암전 중 입력·물리 정지, 복원 뒤 이동·능력 조작을 확인한다.

자동 입력이나 수치 검사가 필요하면 현재 씬의 참조·좌표·입력 방식에 맞춰 검사를 구성한다. 테스트 코드의 보존은 반복 실행의 필요성이 확인된 경우에 정한다. 검사 뒤 만든 입력 기기·콜백을 제거하고 원래 설정을 복원한다. Stop 뒤 가상 기기가 다시 남는지도 확인한다. 자동 입력 검사와 화면 검사는 사람이 직접 플레이하며 확인하는 발견성·난이도 검토를 대신하지 않는다.
