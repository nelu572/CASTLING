# GitHub 하네스

GitHub에서의 협업 규칙과 라벨 체계를 정의한다. 커밋·push·PR·이슈 생성은 사용자가 명시적으로 요청한 경우에만 수행한다.

## 사용자 변경 보호

- 사용자가 수정한 이슈·PR 템플릿, 문구, 라벨 설정은 현재 내용을 확인한 뒤에만 변경한다.
- 하네스 예시와 달라도 템플릿 일관성만을 이유로 삭제·되돌리지 않는다. 변경 의도가 불명확하거나 충돌하면 사용자에게 확인한다.

## PR과 이슈

- 양식 목록과 공통 작성 기준은 [자료 추가 기준과 양식](TEMPLATES.md)에서 관리한다. PR·이슈 양식의 원본은 `.github`에 유지하고 프로젝트 문서용 양식과 중복 보관하지 않는다.
- PR 생성의 상세 절차는 [PR 생성 절차](../skills/AUTO_PR.md)를 따른다.
- PR에는 담당자(Assignees)를 반드시 지정한다.
- GitHub 이슈 생성은 사용자가 명시적으로 요청한 경우에만 수행하며, 상세 절차는 [이슈 생성 절차](../skills/AUTO_ISSUE.md)를 따른다.
- 라벨 생성·변경·삭제는 사용자의 명시 요청이 있을 때만 수행한다.

## 라벨 선택

PR과 필요한 이슈에는 변경 유형 라벨 하나와 관련 영역 라벨을 붙인다. 존재하지 않는 라벨은 자동 생성하지 않는다.

### 변경 유형

| 라벨 | 용도 |
| --- | --- |
| `type:feature` | 신규 기능·콘텐츠 |
| `type:fix` | 오류·회귀 수정 |
| `type:improve` | 기존 동작·사용성 개선 |
| `type:refactor` | 동작 변경 없는 구조 개선 |
| `type:design` | UI·연출·아트 설계 |
| `type:docs` | 문서와 기획 색인 |
| `type:test` | 테스트·검증 환경 |
| `type:chore` | 빌드·패키지·저장소 설정 |

### 게임 영역

| 라벨 | 적용 범위 |
| --- | --- |
| `area:gameplay` | 킹·룩 조작, CASTLING, 퍼즐·목표·진행 |
| `area:scene` | 씬 구성과 전환 |
| `area:input` | Input System과 조작 |
| `area:core` | 공용 값·기반 시스템 |
| `area:ui` | HUD와 메뉴 |
| `area:audio` | BGM·효과음·믹서 |
| `area:art` | 시각 에셋·아트 파이프라인 |
| `area:build` | Unity·패키지·빌드 설정 |

`priority:*`, `status:*`, `good first issue` 같은 운영 라벨은 이슈가 실제로 늘어난 뒤 필요성이 확인되면 추가한다.
