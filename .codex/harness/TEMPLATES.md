# 자료 추가 기준과 양식

편집 원본, 재사용 검사, 제작 결정을 추가할 때 이 기준을 따른다. 기존 폴더의 용도에 맞으면 그 안에 추가하고, 새 역할이 필요할 때만 폴더를 만든다. 파일마다 별도 폴더를 만들 필요는 없다.

## 저장 위치

| 자료 | 위치 | 작성 양식 |
| --- | --- | --- |
| GitHub PR | `.github/PULL_REQUEST_TEMPLATE/` | [작업 PR 양식](../../.github/PULL_REQUEST_TEMPLATE/task.md) |
| GitHub 이슈 | `.github/ISSUE_TEMPLATE/` | [작업 이슈 양식](../../.github/ISSUE_TEMPLATE/task.md) |
| 룸·에셋 사용법과 반복 검사 방법 | `.reference/guides/` | 검사 방법은 [검사 안내 양식](../../.templates/VERIFICATION_TEMPLATE/template.md) |
| 보존할 사용자 결정과 미확정 범위 | `.reference/records/` | [제작 결정 양식](../../.templates/RECORD_TEMPLATE/template.md) |
| 독립 레벨 보관소·레벨별 핵심 해법과 재사용 안내 | `.reference/levels/`의 목록·레벨 카드 | [레벨 보관 카드 양식](../../.templates/LEVEL_LIBRARY_TEMPLATE/template.md) |
| 레벨 분석·레퍼런스 비교·설계안·검증 계획 | 초안은 `.work/<날짜>-<작업명>/`, 보존할 승인 결정은 `.reference/records/` | [레벨 디자인 양식](../../.templates/LEVEL_DESIGN_TEMPLATE/template.md) |
| 게임 에셋의 편집 원본과 생성 도구 | `Tools/Art/` | [자료 양식](../../.templates/RESOURCE_TEMPLATE/template.md)을 바탕으로 해당 폴더의 README에 등록 |
| 반복 실행할 검사 코드 | 실제 실행 방식에 맞는 코드 위치 | [자료 양식](../../.templates/RESOURCE_TEMPLATE/template.md)에 실행 방법·의존성·부작용을 쓰고 [검사 안내 양식](../../.templates/VERIFICATION_TEMPLATE/template.md)에 검사 범위를 명시 |
| 스크린샷·일회성 코드·JSON·로그·시안 | `.work/<날짜>-<작업명>/` | [.work 안내](../../.work/README.md)의 작업별 양식 |

`.codex/harness`에는 계속 적용할 규칙을, `.codex/skills`에는 요청별 작업 절차를 유지한다. 기존 지침에 들어갈 주의점은 해당 파일에 반영한다. 사용법·검사 안내를 추가했다면 해당 지침에서 연결한다.

## 양식 관리

- 이 문서에서 양식 목록·사용법·관리 기준을 관리한다. GitHub가 읽는 PR·이슈 양식은 `.github/<종류>_TEMPLATE/`에, 프로젝트 문서용 양식은 `.templates/<종류>_TEMPLATE/template.md`에 원본을 둔다. 양식 폴더에는 양식 파일을 두고, 사용법·관리 기준은 `.codex/harness`에서 관리한다. 같은 양식을 두 위치에 복사하지 않고 링크로 연결한다.
- 양식의 항목은 용도에 맞게 유지한다. 이슈에는 앞으로 할 작업과 완료 조건을, PR에는 실제 변경과 검증 결과를, 자료·검사·제작 기록에는 해당 양식의 내용을 작성한다.
- 공통 작성 기준은 한글로 간결하게 쓰고, 사실·기대 결과·미확정 사항을 구분하는 것이다. 검증을 적는 양식에는 실행한 범위와 결과를 쓰며 미실행·해당 없음은 이유를 적는다.
- 양식을 추가·이동·삭제하면 위 목록과 관련 작업 절차의 링크를 함께 갱신한다. GitHub 양식은 파일 위치와 이슈 양식의 frontmatter를 유지한다. 생성 절차·제목·라벨 규칙은 [GitHub 하네스](GITHUB.md)와 연결된 절차를 따른다.

## 추가 순서

1. 다음 작업에서 사용할 이유와 읽거나 실행할 작업을 정한다. 같은 역할의 파일·폴더가 있는지 먼저 확인한다.
2. 알맞은 양식으로 안내를 작성하고 필요한 자료만 추가한다. 새 자료 폴더에는 README를 두며, 기존 폴더에 추가할 때는 기존 안내를 갱신한다.
3. 원본과 결과물의 관계, 실행·편집 방법, 덮어쓰는 파일, 검증 상태를 적는다. 실행 경로가 없거나 미검증이면 그대로 표시한다.
4. 관련 하네스·작업 절차·사용 안내에서 연결한다. 새 작업 분야가 생기면 `AGENTS.md`의 읽기 경로도 갱신한다.
5. 링크와 실행 경로, Git 제외 여부를 확인한다. 검사를 실행하지 않았다면 통과 기록을 남기지 않는다.

양식의 설명과 자리표시자는 실제 내용으로 바꾸고, 적용되지 않는 항목은 생략한다. 기존 문서를 일괄 재작성하거나 자료를 자동 복원하는 기준으로 사용하지 않는다.

## 임시 작업 폴더

레벨 작업은 [레벨 디자인 절차](../skills/LEVEL_DESIGN.md)에 따라 양식의 필요한 단계만 채운다. 게임별 레퍼런스는 양식의 같은 프로필 표를 반복해 비교하며, 처음부터 별도 프로필 폴더를 만들지 않는다. 초안·측정 결과·플레이테스트 기록은 작업 폴더에서 관리하고, 승인된 장기 결정만 기존 챕터 기록에 합치거나 제작 결정 양식으로 보존한다. 승인된 설계의 적용 범위·버전·사용자 승인 근거를 함께 남기고, 현재 씬 수치를 영구 기준으로 승격하지 않는다. 반복 사용할 레퍼런스 관찰을 사용 안내에 보존할 때는 출처·관찰 범위·갱신 조건을 붙인다.

`.work` 루트와 README는 유지한다. 작업별 폴더는 자료가 필요할 때 만들고, 저장 경로·상태별 보관·정리 시점·사용 중인 파일 처리는 [.work 안내](../../.work/README.md)를 따른다. `.work/README.md`만 Git에 보존하며, 작업별 하위 폴더는 전체를 제외한다.

독립 레벨을 보존할 때는 [레벨 보관소](../../.reference/levels/README.md)에 목록과 카드를 추가한다. 카드에는 원자료 정리 뒤에도 읽을 핵심 공간·해법·대안·복구·검증 한계를 남기고, 승인·평가 이력은 제작 결정 기록에 연결한다. 미제작 아이디어와 실제 통과 경로를 구분하며 일회성 설계·로그 묶음을 자동 승격하지 않는다.

보존이 필요해지면 필요한 원본·결정·검사 방법을 위의 정식 위치에 안내와 함께 추가하고, 임시 묶음 전체를 옮기지 않는다.

작성 예시는 [아트 원본과 생성 도구](../../Tools/Art/README.md), [재사용 검증 방법](../../.reference/guides/VERIFICATION_CHECKS.md)을 참고한다.
