# 공허 추락과 구간 재시작

사용자가 승인한 규칙은 한 명이 공허로 떨어지면 둘 다 해당 구간 앞에서 다시 시작하는 방식이다.

## 배치

룩 이동 홈 x68–82의 후반 x76–82에서 하부 바닥을 끊었다. 왼쪽 x71–76에는 높이 −5의 바닥, x68–71에는 높이 −2의 중간 복귀 발판 하나가 이어진다. 바깥 모서리와 안쪽 접합부는 반경 1의 Dark OuterR1·InnerR1로 연결하고 공허 앞 바닥 끝도 OuterR1로 마감했다. 지형 타일의 크기는 1이고 배경·카메라 영역은 기존 설정을 사용한다.

공허를 건너는 기본 경로는 룩의 좌우 이동으로 오른쪽에 착지한 뒤 지상 F로 킹을 넘겨주고, 룩이 다시 건너와 합류하는 순서다. 룩 이동을 왼쪽에서 일찍 놓으면 복귀 바닥에 떨어질 수 있고, 후반 공허 위에서 놓으면 낙사한다. 첫 통로 다음 높이 −4의 홈은 기존 안전 바닥을 사용한다.

## 사망 판정과 복귀

`Grid/Room_01/Puzzles/VoidFallZone`은 화면 아래 y−12–−14의 Trigger다. 캐릭터의 실제 Rigidbody2D가 닿았을 때만 판정하며, 어느 한 명이 닿으면 두 명 모두 재시작한다. 같은 순간 두 명이 닿아도 한 번만 처리한다.

재시작 지점은 `Entries/RookGapStartPositions`의 KingStart x62.5, RookStart x65.5다. 스위치를 지난 뒤 긴 홈 앞의 안전한 평지이며 시작 높이는 기존 최초 시작점과 같은 1.6·1.5다. 기존 첫 시작점의 참조는 그대로다.

기존 Fade 오버레이를 0.2초씩 암전·복원한다. 그 동안 게임 시간을 멈추고 두 캐릭터의 입력·이동과 룩 직선 이동을 중단한다. 암전 안에서 위치와 속도를 초기화하고 카메라 추적을 다시 계산한다. 복원이 끝나면 기존 입력·이동 활성 상태와 시간 배율을 돌려준다. 재시작 처리 중 컴포넌트가 꺼져도 시간·입력·화면 상태를 복구한다.

공허 판정 전에 쓰는 F는 기존 거리·시야·공중 사용·재사용 제한 없는 규칙을 따른다. 새 사망 처리는 `VoidRespawnZone.cs`, 재사용 Trigger 구성은 `Assets/Prefabs/Gameplay/VoidFallZone.prefab`에 있다. 캐릭터·복귀 위치·Fade·카메라 타깃 그룹 참조와 Trigger 크기는 씬의 프리팹 인스턴스에 저장한다.

## 검증

[VerifyVoidRespawn.cs.txt](verification/VerifyVoidRespawn.cs.txt)를 새 Play Mode에서 Unity MCP execute_code로 실행한다. 사례별 시작 위치만 배치하고, 룩의 실제 이동·해제와 킹의 실제 걷기로 추락시킨다. 룩 단독 추락, 킹 단독 추락, 동시 추락에서 두 명의 복귀와 재시작 횟수를 확인한다. 암전 중 입력·물리 시간 정지, 복원 뒤 F와 룩 이동·일반 조작도 검사한다.

결과는 SessionState의 `CASTLING.VoidRespawn`에서 읽는다. Stop 후 [임시 입력 정리](verification/CleanupFollowupInput.cs.txt)를 실행한다. 검사 본문은 중복 실행을 차단해 같은 키보드와 캐릭터를 여러 콜백이 조작하지 않도록 한다.

전체 진행 경로는 기존 [후속 구간 하네스](FOLLOWUP_COOPERATION.md)를 사용하며, 공허 추가 후에도 사망 없이 재합류할 수 있는지 확인한다. JSON과 캡처는 로컬 산출물이다.

2026-10-02 최종 배치에서 추락·재시작·조작 복원 8건을 모두 통과했다. 룩 추락, 킹 추락, 동시 추락에서 각각 한 번씩 총 3회 재시작했으며, 암전 동안 입력·이동과 시간 배율 정지는 213회 표본에서 정상 상태였다. 전체 경로는 저장된 시작점부터 낙사와 위치·속도 쓰기 없이 통과했다. Raycast에서 x77·79·81에는 바닥 충돌이 없고 x74의 복귀 바닥과 x84의 착지면에는 충돌이 있음을 확인했다. Editor Console 오류·경고와 씬의 누락 참조는 0건이었다.
