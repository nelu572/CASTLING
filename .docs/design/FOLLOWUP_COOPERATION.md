# 후속 구간: 스위치 역할 넘기기와 룩의 좌우 이동

Chapter_01의 x30–79에 해당하는 협동 구간이다. 첫 통로와 x80 이후 지형에 연결되며 기존 이동 설정과 F·룩 능력의 규칙을 사용한다.

## 스위치 통로

높이 0의 넓은 바닥과 높이 8의 연결된 지붕 사이에 문을 둔다. 스위치는 x36·48, 문은 x42다. 양쪽 스위치 중 하나를 캐릭터가 밟고 있는 동안 문이 열린다. 점프하거나 떠나면 해당 스위치는 해제된다. 한 번 눌러 영구 개방되는 장치는 아니다.

한 명이 가까운 스위치를 맡고 상대가 문을 지나 반대편 스위치를 맡는다. 처음 스위치에 남았던 사람이 통과한 뒤 둘이 함께 진행한다. 양쪽 스위치를 밟은 상태에서 F로 역할을 교환할 수도 있다. 이 구간은 F를 반드시 쓰게 하는 구간으로 취급하지 않는다.

스위치는 바닥에 낮게 묻고 연결선을 바닥 안에 넣었다. 문의 셔터는 지붕 뒤로 들어간다. 텍스트 대신 눌린 표면과 밝아진 표시로 상태를 보여준다. 재사용 구성은 `Assets/Prefabs/Gameplay/PressureGatePair.prefab`에 저장한다. `PressurePlateSwitch`가 발 위치를 검사하고 `PressureGate`가 연결된 스위치와 문을 관리한다.

발을 뗄 때 캐릭터가 문 안에 있다면 몸체가 빠져나간 뒤 닫는다. 닫힌 콜라이더가 캐릭터 안에 생기는 것을 방지한다. 문 안에 캐릭터가 없는 상태에서 스위치가 해제되면 즉시 통행을 막는다.

## 룩 이동과 지상 교환

x60–74의 긴 홈은 일반 점프로 바로 건너기 어렵고, 양쪽에는 멈춰 설 수 있는 넓은 바닥을 둔다. 룩이 오른쪽 Shift와 방향키로 건너가 착지한 뒤 F를 쓴다. 킹은 건너편 바닥을 받고, 룩은 왼쪽에서 다시 건너와 합류한다. 공중에서 F를 누르는 타이밍은 요구하지 않는다.

Shift를 일찍 놓으면 높이 −5의 안전한 바닥에 떨어진다. 왼쪽 발판 밑으로 걸어간 뒤 높이 −4·−2의 발판으로 일반 점프를 이어 출발 바닥에 돌아올 수 있다. 하부 바닥을 걷는 것만으로 오른쪽으로 진행하는 길은 없다. 지붕과 바닥은 큰 덩어리로 연결하고 출발면과 지붕 단차는 팔레트의 완전한 OuterR2 묶음으로 마감한다. 착지면은 OuterSmall로 작게 마감한다. 큰 곡면을 사용했을 때 킹이 벽에 붙어 점프한 뒤 곡면을 타고 올라가던 우회를 실제 입력 검사에서 찾아 수정했다. 타일 이름의 y 순번은 실제 스프라이트 좌표에 맞춰 배치한다.

## 검증

- 각 검사 후 Stop 상태에서 [임시 입력 정리](verification/CleanupFollowupInput.cs.txt)를 실행한다. Play 진입 때의 Input System 기기 목록이 Stop 후 복원되어, 검사 중 제거한 가상 기기가 다시 남을 수 있다. 정리는 이 하네스 이름의 비네이티브 키보드만 제거한다.
- [연속 경로 검사](verification/VerifyFollowupRoute.cs.txt): 저장된 시작점부터 실제 PlayerInput 키 이벤트만 사용한다. 진행 중 위치·속도를 직접 쓰지 않는다. 첫 통로, 문 양쪽 스위치, F 역할 교환, 룩 이동과 지상 F, 최종 재합류를 확인한다.
- [안전·복귀 검사](verification/VerifyFollowupEdges.cs.txt): 사례별 시작 위치만 배치한다. 이후 실제 입력으로 문 차단, 점프 해제, 문 안 몸체 보호, 킹의 일반 점프 시도, 룩 이동 중 해제와 하부 복귀를 검사한다.
- [하부 우회 검사](verification/VerifyFollowupSoloBypass.cs.txt): 킹을 하부 바닥과 각 복귀 발판에 배치한 뒤 실제 이동·점프 입력으로 오른쪽 착지 바닥에 도달할 수 있는지 검사한다.
- 결과는 SessionState에서 읽는다. 결과 JSON과 캡처는 커밋하지 않는다. 자동 입력 검사는 두 사람이 직접 확인하는 발견성과 체감 난이도를 대신하지 않는다.

각 검사 본문은 새로 진입한 Play Mode에서 하나씩 Unity MCP execute_code로 실행한다. 검사가 끝나면 Stop 후 다음 검사를 위해 Play를 다시 시작한다. 같은 Play 세션에서 가상 입력 기기를 교체하며 여러 검사를 이어 실행하면 PlayerInput의 기기 연결 상태가 달라져 입력이 누락될 수 있다. SessionState의 `CASTLING.FollowupRoute`, `CASTLING.FollowupCameraMetrics`, `CASTLING.FollowupEdges`, `CASTLING.FollowupSoloBypass`를 읽는다. 임시 가상 키보드를 두 PlayerInput의 입력 기기로 지정해 검사 중 실제 키보드 이벤트와 섞이지 않게 한다. 검사가 끝나면 가상 기기를 제거하고 기존 입력 기기·자동 전환·입력 포커스·백그라운드 설정을 복원한다. 사람의 플레이 확인은 검증을 종료하고 새로 Play에 진입해 수행한다.
