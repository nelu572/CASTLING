# 후속 구간: 스위치 역할 넘기기와 룩의 좌우 이동

Chapter_01의 x32–95에 해당하는 협동 구간이다. 맵 전체를 가로로 넓히면서 스위치 앞, 스위치 통과 후, 마지막 착지면의 평지에 각각 4칸을 추가했다. 스위치와 문의 내부 간격, 룩 이동 홈의 폭은 유지한다. 기존 이동 설정과 F·룩 능력의 규칙을 사용한다. 뒤쪽 지형 초안은 삭제했고, 재합류 바닥을 x95까지 남긴 뒤 x95–97의 벽으로 막았다. 현재는 이 구간에서 제작 범위가 끝나며 완료 판정은 없다.

## 스위치 통로

높이 0의 바닥과 높이 8의 연결된 지붕 사이에 문을 둔다. 스위치는 x40·52, 문은 x46다. 프리팹 전체를 옮겨 스위치와 문 사이의 간격 6을 유지했다. 양쪽 스위치 중 하나를 캐릭터가 밟고 있는 동안 문이 열린다. 점프하거나 떠나면 해당 스위치는 해제된다. 한 번 눌러 영구 개방되는 장치는 아니다.

한 명이 가까운 스위치를 맡고 상대가 문을 지나 반대편 스위치를 맡는다. 처음 스위치에 남았던 사람이 통과한 뒤 둘이 함께 진행한다. 양쪽 스위치를 밟은 상태에서 F로 역할을 교환할 수도 있다. 이 구간은 F를 반드시 쓰게 하는 구간으로 취급하지 않는다.

스위치는 바닥에 낮게 묻고 연결선을 바닥 안에 넣었다. 문의 셔터는 지붕 뒤로 들어간다. 텍스트 대신 눌린 표면과 밝아진 표시로 상태를 보여준다. 재사용 구성은 `Assets/Prefabs/Gameplay/PressureGatePair.prefab`에 저장한다. `PressurePlateSwitch`가 발 위치를 검사하고 `PressureGate`가 연결된 스위치와 문을 관리한다.

발을 뗄 때 캐릭터가 문 안에 있다면 몸체가 빠져나간 뒤 닫는다. 닫힌 콜라이더가 캐릭터 안에 생기는 것을 방지한다. 문 안에 캐릭터가 없는 상태에서 스위치가 해제되면 즉시 통행을 막는다.

## 룩 이동과 지상 교환

x68–82의 긴 홈은 일반 점프로 바로 건너기 어렵고, 양쪽에는 멈춰 설 수 있는 바닥을 둔다. 맵 확장 전과 동일한 폭 14다. 룩이 오른쪽 Shift와 방향키로 건너가 착지한 뒤 F를 쓴다. 킹은 건너편 바닥을 받고, 룩은 왼쪽에서 다시 건너와 합류한다. 공중에서 F를 누르는 타이밍은 요구하지 않는다.

홈 왼쪽에서 Shift를 일찍 놓으면 높이 −5의 x71–76 바닥에 떨어진다. 복귀 동선은 높이 −2의 중간 발판 하나를 거쳐 출발 바닥으로 올라오는 형태다. 이전의 −4 잔단차를 없애고 중간 발판을 x68–71로 넓혔다. 출발면과 중간 발판의 바깥 모서리, 수직면에서 아래 평지로 이어지는 안쪽 모서리는 같은 반경 1의 OuterR1·InnerR1 묶음으로 연결한다. 작은 계단을 반복하는 대신 연결된 큰 바닥 덩어리 안에서 두 번의 점프가 읽히게 한다. 아래 바닥 끝도 OuterR1로 마감한다.

후반 x76–82는 하부 바닥을 끊은 공허다. 화면 아래로 떨어지면 한 명의 낙사로 둘 다 구간 앞에서 재시작한다. 복귀 규칙과 배치는 [공허 문서](VOID_RESPAWN.md)를 따른다. 하부 바닥을 걷는 것만으로 오른쪽으로 진행하는 길은 없다. 지붕 단차는 완전한 OuterR2 묶음을 사용하며, 오른쪽 착지면은 OuterSmall로 작게 마감한다. 큰 곡면을 사용했을 때 킹이 벽에 붙어 점프한 뒤 곡면을 타고 올라가던 우회를 실제 입력 검사에서 찾아 수정했다. 타일 이름의 y 순번은 실제 스프라이트 좌표에 맞춰 배치한다.

## 검증

- 각 검사 후 Stop 상태에서 [임시 입력 정리](verification/CleanupFollowupInput.cs.txt)를 실행한다. Play 진입 때의 Input System 기기 목록이 Stop 후 복원되어, 검사 중 제거한 가상 기기가 다시 남을 수 있다. 정리는 이 하네스 이름의 비네이티브 키보드만 제거한다.
- [연속 경로 검사](verification/VerifyFollowupRoute.cs.txt): 저장된 시작점부터 실제 PlayerInput 키 이벤트만 사용한다. 진행 중 위치·속도를 직접 쓰지 않는다. 첫 통로, 문 양쪽 스위치, F 역할 교환, 룩 이동과 지상 F, 최종 재합류를 확인한다. 넓어진 착지면에서는 앞서 있는 룩이 먼저 문을 통과하도록 역할을 정한다. 긴 홈 앞에서는 룩이 킹을 일반 점프로 넘어 앞으로 나선 뒤 바닥에서 직선 이동을 시작한다. 직선 이동으로 앞에 있는 킹을 밀어 홈에 떨어뜨리는 입력 순서를 피한다.
- [안전·복귀 검사](verification/VerifyFollowupEdges.cs.txt): 사례별 시작 위치만 배치한다. 이후 실제 입력으로 문 차단, 점프 해제, 문 안 몸체 보호, 킹의 일반 점프 시도, 룩 이동 중 해제와 하부 복귀를 검사한다.
- [하부 우회 검사](verification/VerifyFollowupSoloBypass.cs.txt): 킹을 하부 바닥과 각 복귀 발판에 배치한 뒤 실제 이동·점프 입력으로 오른쪽 착지 바닥에 도달할 수 있는지 검사한다.
- [낙사·재시작 검사](verification/VerifyVoidRespawn.cs.txt): 룩·킹 단독 추락과 동시 추락에서 둘 다 복귀하는지, 복원 뒤 F·룩 이동·일반 조작이 동작하는지 확인한다. 연속 경로 검사는 재시작 횟수가 0인 것도 확인한다.
- 결과는 SessionState에서 읽는다. 결과 JSON과 캡처는 커밋하지 않는다. 자동 입력 검사는 두 사람이 직접 확인하는 발견성과 체감 난이도를 대신하지 않는다.

각 검사 본문은 새로 진입한 Play Mode에서 하나씩 Unity MCP execute_code로 실행한다. 검사가 끝나면 Stop 후 다음 검사를 위해 Play를 다시 시작한다. 같은 Play 세션에서 가상 입력 기기를 교체하며 여러 검사를 이어 실행하면 PlayerInput의 기기 연결 상태가 달라져 입력이 누락될 수 있다. SessionState의 `CASTLING.FollowupRoute`, `CASTLING.FollowupCameraMetrics`, `CASTLING.FollowupEdges`, `CASTLING.FollowupSoloBypass`를 읽는다. 임시 가상 키보드를 두 PlayerInput의 입력 기기로 지정해 검사 중 실제 키보드 이벤트와 섞이지 않게 한다. 검사가 끝나면 가상 기기를 제거하고 기존 입력 기기·자동 전환·입력 포커스·백그라운드 설정을 복원한다. 사람의 플레이 확인은 검증을 종료하고 새로 Play에 진입해 수행한다.
