# Chapter_01 카메라 영역과 구도

씬 안의 공유 Cinemachine 카메라와 영역 설정이다.

- 카메라 영역: x−3–161, y−8–22. 기존 가로 진행 범위는 유지하고 위아래 범위를 현재 지형에 맞춰 조정했다.
- 기본 직교 크기와 최소값: 8. 사용자 요청으로 Dev_Gameplay의 두 카메라에서 기본 크기와 최소값이 모두 8인 것을 직접 확인했다. 앞선 Chapter_01의 6 설정을 8로 바꿔 기본 화면을 더 넓게 보여준다.
- 공유 화면 확대 범위: 8–14.5. 최대 화면 높이 29를 영역 높이 30보다 작게 두었다. 둘이 멀리 떨어졌을 때 Confiner의 유효 영역이 높이 0으로 줄어 카메라가 영역 중앙으로 이동하던 경우를 피한다.
- Group Framing CenterOffset과 Position Composer ScreenPosition: y−0.18. 바닥 아래 빈 면의 비중을 줄이고 지붕과 이동 공간을 보여준다.
- 타깃 그룹의 프레이밍 반경은 킹 1.65, 룩 1.45로 설정했다. 몸체와 피벗의 차이를 포함해, 두 말의 높이 차가 클 때 발끝이 잘리던 경우를 수정했다. 실제 콜라이더 크기는 바꾸지 않았다.
- 기존 추적 완화값, 화면 비율과 레터박스는 유지했다. 카메라 코드·플레이어 프리팹·Dev_Gameplay는 변경하지 않았다.

첫 통로와 후속 구간의 실제 입력 경로·추락 복귀 중 카메라 검사는 [후속 구간 하네스](FOLLOWUP_COOPERATION.md)를 따른다. 검사 중 콜라이더 잘림과 카메라 영역 이탈을 확인한다.

추가 검사는 왼쪽 경계, 통로 양쪽 분리, 첫 구간부터 다음 바닥까지 분리, 약 52칸 거리 분리, 중반 낮은 바닥, 높은 발판의 점프 높이와 목표 지점, 오른쪽 목표 지점이다. 검증 때만 두 몸체의 시뮬레이션을 잠시 멈춰 위치를 배치한 뒤 실제 카메라가 따라온 결과를 검사하고 원래 상태를 복원한다. 백그라운드 실행도 검증 동안만 켠다. 전체 챕터의 양 끝처럼 카메라 최대 폭보다 멀리 떨어진 모든 조합을 검증한 것은 아니다.

추가 배치를 다시 검사할 수 있는 본문: [VerifyChapterCameraScenarios.cs.txt](verification/VerifyChapterCameraScenarios.cs.txt). 이 본문은 몸체를 잠시 고정해 화면 구도만 검사한다. 결과는 SessionState의 `CASTLING.CameraScenarios`에서 읽는다. 검사 후 몸체 시뮬레이션과 백그라운드 실행 설정을 복원한다. 결과 JSON과 캡처는 로컬에만 보관한다.
