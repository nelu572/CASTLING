# Chapter_01 카메라 영역과 구도

씬 안의 공유 Cinemachine 카메라와 영역 설정이다.

- 카메라 영역: x−7–97, y−8–22. 맵 전체의 평지를 늘려 가로 폭을 80에서 104로 확장했다. BoxCollider2D 크기는 (104, 30), Offset은 (45, 7)이다. 오른쪽 경계는 마지막 재합류 바닥의 마감 벽이다. 위쪽 구도와 실제 하부 동선은 유지한다.
- 기본 직교 크기와 최소값: 8. 사용자 요청으로 Dev_Gameplay의 두 카메라에서 기본 크기와 최소값이 모두 8인 것을 직접 확인했다. 앞선 Chapter_01의 6 설정을 8로 바꿔 기본 화면을 더 넓게 보여준다.
- 공유 화면 확대 범위: 8–14.5. 영역 높이 30은 최대 화면 높이 29보다 크다. 둘이 멀리 떨어졌을 때도 Confiner의 유효 영역을 남긴다.
- Group Framing CenterOffset과 Position Composer ScreenPosition: y−0.27. 타깃을 화면 아래쪽에 두어 위쪽 배경의 비중을 늘린다. 영역 확장과 실제 화면 구도 조정을 함께 적용한다.
- 타깃 그룹의 프레이밍 반경은 킹 1.65, 룩 1.45로 설정했다. 몸체와 피벗의 차이를 포함해, 두 말의 높이 차가 클 때 발끝이 잘리던 경우를 수정했다. 실제 콜라이더 크기는 바꾸지 않았다.
- 기존 추적 완화값, 화면 비율과 레터박스는 유지했다. 카메라 코드·플레이어 프리팹·Dev_Gameplay는 변경하지 않았다.

첫 통로와 후속 구간의 실제 입력 경로·추락 복귀 중 카메라 검사는 [후속 구간 하네스](FOLLOWUP_COOPERATION.md)를 따른다. 검사 중 콜라이더 잘림과 카메라 영역 이탈을 확인한다.

바닥 아래의 불필요한 빈틈을 채우고 위쪽 구도를 조정한 뒤에는 통로 앞 킹과 높이 −4 바닥의 룩이 분리된 구도, 열린 홈 아래 킹과 높이 0 착지면의 룩이 분리된 구도를 함께 검사한다. 기본·최소 크기 8과 기존 추적 완화값은 유지한다.

추가 검사는 왼쪽 경계, 통로 양쪽 분리, 첫 구간부터 다음 바닥까지 분리, 약 48칸 거리 분리, 홈의 하부 바닥, 마지막 재합류 바닥, 오른쪽 마감 벽이다. 삭제된 후반 발판과 목표 지점은 검사 대상에서 제거했다. 검증 때만 두 몸체의 시뮬레이션을 잠시 멈춰 위치를 배치한 뒤 실제 카메라가 따라온 결과를 검사하고 원래 상태를 복원한다. 백그라운드 실행도 검증 동안만 켠다. 맵의 폭과 한 화면의 폭은 다르며, 카메라 최대 폭보다 멀리 떨어진 모든 조합을 검증한 것은 아니다.

추가 배치를 다시 검사할 수 있는 본문: [VerifyChapterCameraScenarios.cs.txt](verification/VerifyChapterCameraScenarios.cs.txt). 이 본문은 몸체를 잠시 고정해 화면 구도만 검사한다. 결과는 SessionState의 `CASTLING.CameraScenarios`에서 읽는다. 검사 후 몸체 시뮬레이션과 백그라운드 실행 설정을 복원한다. 결과 JSON과 캡처는 로컬에만 보관한다.

2026-10-02 가로 확장 후 배치 9건을 모두 통과했다. 약 48칸 거리 분리에서는 최대 크기 14.5로 두 몸체를 담았고, 카메라 영역 이탈은 수치 오차 범위인 0.000006칸 이하였다. 실제 입력 연속 경로 2,205회와 안전·복귀 경로 1,560회에서도 캐릭터 잘림은 0회였다.

공허 추가 후 연속 경로는 3,728회, 안전·복귀 경로는 1,747회 검사에서 잘림이 0회였다. 안전·복귀 검사에서는 공허로 추락 중인 몸체와 암전 중의 프레임을 제외한다. 낙사 중 화면 아래로 사라지는 것은 사망 연출에 해당한다. 재시작 시 씬에 연결된 타깃 그룹을 갱신하고 카메라의 이전 추적 상태를 초기화한다.

복귀 지형을 중간 발판 하나와 같은 반경의 곡선으로 정리한 뒤에는 연속 경로 2,368회, 킹·룩 복귀를 포함한 안전 검사 1,210회에서 잘림이 0회였다. 카메라 영역과 Inspector 설정은 바꾸지 않았다.
