# 첫 구간: 룩이 낮은 통로를 확보하고 킹을 넘겨주기

사용자가 승인한 크기 차이와 지상 CASTLING 구조를 사용하는 Chapter_01 첫 구간이다.

## 지형과 의도

바닥은 높이 0으로 평평하게 연결한다. x8–18의 아이보리 천장 아래 유효 통로 높이는 2다. 기존 충돌 높이는 룩 1.65, 킹 2.87이므로 작은 룩은 통과하고 킹은 물리적으로 막힌다. 캐릭터 크기·콜라이더·물리 수치와 능력 사용 조건은 바꾸지 않았다. 지붕은 x−30–30 전체에서 높이 8–44를 덮고 낮은 통로와 이어진다. 위쪽 외곽선은 화면 밖에 두어 독립된 부유 블록 대신 방의 천장으로 읽힌다.

통로 양쪽에는 두 말이 멈춰 설 수 있는 넓은 바닥을 둔다. 룩이 킹 앞에서 출발하도록 시작 위치는 킹 x2.5, 룩 x5로 배치했다. 입구에서 킹이 룩의 진로를 막아 불필요하게 점프해야 하는 상황을 피한다.

넓은 검정 기반과 아이보리 천장에는 기존 팔레트를 사용한다. 낮은 통로 양 끝은 OuterR1로, 큰 천장과 내려오는 면의 안쪽 접합은 InnerR2로 마감했다. InnerR2 묶음의 채움 행·열을 천장과 통로 안에 겹쳐 조립해 작은 계단 없이 원호가 이어진다. Dev_Gameplay에서 확인한 두꺼운 지형과 모서리 언어를 유지한다. 후반 지형은 x30 이후 기존 배치에 그대로 연결된다.

## 플레이 순서

1. 룩이 낮은 통로를 걸어서 지나간다. 킹은 입구에서 막힌다.
2. 룩이 통로 너머의 넓은 바닥에 멈춘 뒤 F를 누른다.
3. 킹은 건너편 바닥을 받고, 룩은 입구 쪽 위치를 받는다.
4. 룩이 다시 낮은 통로를 걸어서 지나가 킹과 합류한다.
5. 두 말이 다음 지형으로 걸어서 진행한다.

점프·직선 이동·공중 교환과 입력 타이밍 맞추기를 요구하지 않는다. 캐릭터 전용 충돌 레이어나 새 장치 없이 기존 몸체 크기 차이를 사용한다.

## 검증

Unity Play Mode에서 기존 PlayerInput에 실제 키 이벤트를 전달했다. 협동 경로는 저장된 시작 위치부터 시작했으며 진행 중 위치·속도를 직접 설정하지 않았다. D·방향키·F만 사용해 두 말 모두 x30 이후 바닥에 도착했다. F 직전에는 두 말 모두 바닥에 서 있었고 수평·수직 속도도 0에 가까웠다. F 이벤트는 1회였다.

킹 단독 걷기와 반복 점프 시도는 통로를 통과하지 못했다. 통로 안에서 너무 일찍 F를 쓰면 킹이 낮은 공간에 놓일 수 있지만, 다시 F를 눌러 안전한 시작 쪽으로 복구하고 룩이 걸어 나올 수 있음을 확인했다. 교환 사용 조건은 사용자 지정대로 제한하지 않는다.

재실행 본문은 [VerifyFollowupRoute.cs.txt](verification/VerifyFollowupRoute.cs.txt)이며, 첫 통로부터 스위치·룩 이동까지 연속으로 검사한다. 실행·입력 정리 절차는 [후속 구간 문서](FOLLOWUP_COOPERATION.md)를 따른다. 결과는 SessionState에서 확인하며 JSON·캡처는 로컬에만 보관한다. 사람이 직접 플레이했을 때의 발견성과 체감 난이도는 별도로 확인한다.
