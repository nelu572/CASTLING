# 자동 커밋

사용자가 `자동 커밋`, `커밋 올려줘`, `변경사항 커밋`, `커밋 분할`처럼 커밋을 명시적으로 요청했을 때만 사용한다.

## 절차

1. `git status`, `git diff`, `git diff --staged`로 변경사항과 충돌 여부를 확인한다.
2. 독립적으로 되돌릴 수 있는 기능 단위로 파일을 묶는다. `.meta` 파일과 테스트는 대응 원본 구현과 반드시 같은 묶음에 포함한다.
3. 커밋 계획(메시지와 포함 파일)을 사용자에게 제시하고 승인받는다.
4. 승인된 묶음만 순서대로 stage·commit하고, 각 커밋 결과를 확인한다.
5. 커밋 완료 뒤 해시와 메시지를 요약한다. push는 별도 요청일 때만 한다.

## 메시지 규칙

- 형식: `<type>(<scope>): <한글 설명>`
- `type`과 `scope`는 영어, 설명은 한글로 작성한다. scope는 모든 커밋에 반드시 하나를 사용한다.

| Type | 적용 기준 |
| --- | --- |
| `feat` | 새 게임 기능·콘텐츠 추가 |
| `fix` | 오류·회귀 수정 |
| `refactor` | 동작 변경 없는 구조 개선 |
| `test` | 자동 테스트·검증 코드 변경 |
| `docs` | 기획·프로젝트·Notion 문서 변경 |
| `chore` | 빌드·패키지·저장소·도구 설정 변경 |
| `perf` | 기능을 유지하는 성능 개선 |

| Scope | 적용 범위 |
| --- | --- |
| `Gameplay` | 킹·룩 조작, CASTLING, 퍼즐 오브젝트·목표·진행 |
| `Scene` | 씬 구성·전환·개발 씬 |
| `Input` | Input System과 조작 |
| `Core` | 공용 값·기반 시스템 |
| `UI` | HUD·메뉴 |
| `Audio` | BGM·효과음·믹서 |
| `Art` | 시각 에셋·아트 파이프라인 |
| `Build` | Unity·패키지·빌드 설정 |
| `Repo` | README·저장소 루트 문서·설정 |
| `Notion` | Notion 원문과 로컬 안내서 |
| `Harness` | 작업 절차와 하네스 문서 |
| `Test` | 테스트·검증 환경 |

- scope는 하나만 사용하고 복수 scope를 조합하지 않는다. 위 영역으로 분류할 수 없는 기능이 실제로 생기면 그때 별도 scope를 추가한다.
- 예: `feat(Gameplay): 위치 교환 기능 추가`, `docs(Harness): PR 절차 추가`.

## Unity 점검

- `Library/`, `Temp/`, `Logs/`, `obj/`, 생성된 솔루션 파일은 커밋 대상에서 제외한다.
- 새·이동·삭제된 `Assets` 원본은 대응 `.meta` 파일까지 포함됐는지 확인한다.
- `ProjectSettings/`와 `Packages/` 변경은 의도와 영향 범위를 커밋 계획에 명시한다.
- 커밋 전 검증은 [UNITY_VERIFY.md](UNITY_VERIFY.md)를 따른다.
