# 이슈 생성

사용자가 GitHub 이슈 생성을 명시적으로 요청했을 때만 사용한다. 이슈는 작업 단위가 명확하고 추적이 필요한 경우에만 만든다.

## 준비 확인

1. 현재 저장소와 열린 이슈를 확인해 같은 목적의 이슈가 있는지 찾는다.
2. 이슈의 목표, 완료 조건, 포함하지 않는 범위를 기획서와 사용자 요청에서 확인한다.
3. [GITHUB.md](../harness/GITHUB.md)에서 변경 유형 하나와 관련 영역 라벨을 고른다. GitHub에 실제 존재하는 라벨만 적용한다.
4. 담당자가 사용자 요청에 있으면 지정한다. 담당자가 없으면 미지정으로 둔다.

## 제목과 본문

- 제목: `[Feature]`, `[Fix]`, `[Improve]`, `[Refactor]`, `[Design]`, `[Docs]`, `[Test]`, `[Chore]` 중 하나로 시작하는 한글 제목
- 본문은 [.github/ISSUE_TEMPLATE/task.md](../../.github/ISSUE_TEMPLATE/task.md) 양식을 사용한다.
- 미확정 기획을 이슈에서 확정하지 않는다. 결정이 필요하면 `결정 필요` 항목으로 남긴다.

## 생성

- 이슈 제목, 본문 요약, 담당자, 라벨을 먼저 사용자에게 보여 준다.
- 사용자가 생성 요청을 유지하면 `gh issue create`로 생성한다.
- 생성 뒤 URL, 제목, 담당자, 라벨을 보고한다.
