# Chapter_01 배경

2026-10-05 · [이슈 #5](https://github.com/nelu572/CASTLING/issues/5)

## 재작업 기준

이전 배경 커밋을 해제한 뒤 재작업했다. 현재 구현과 과거 시안의 기록을 구분하며, 커밋 여부와 별개로 배경 아트의 최종 확정안은 아니다.

- 배경 구조물의 색은 **검정과 흰색 두 종류**로 잡는다. 인게임 흑백 플랫폼과 같은 색의 기준을 사용한다.
- 각 거리 층 안에 검정 구조물과 흰 구조물을 함께 배치한다. 한 층 전체를 하나의 색으로 고정하지 않는다.
- Near·Mid·Far는 같은 두꺼운 플랫폼과 단차를 기준으로 한다. 거리에 따른 화면 크기·세부 가독성·겹침·패럴랙스로 구분한다.
- 층의 간격·크기·윤곽·패럴랙스로 거리 관계를 먼저 잡는다. 먼저 하강 구간 한 화면에서 흑백 구성과 실제 플레이 플랫폼의 구분을 검토한 뒤 전체 구간에 적용한다.

## 현재 Unity 배치: 노션 기준 재기획 적용 · 2026-10-05

### 커밋 전 SkyTone 참조 정리

사용자가 이미지를 제외하고 기존 스프라이트로 교체하도록 선택했다. SkyTone은 새 `Chapter_01/SkyTone.png` 대신 기존 모듈형 atlas의 `Fill_0_0` Sprite를 참조한다. SpriteRenderer의 Sliced 크기 (105, 30), 위치와 정렬은 유지하며 RGB tint는 모두 206.5/255로 설정했다. 약한 세로 그라데이션을 기존 평균 밝기의 중성 단색으로 바꿨다. 새 이미지·머티리얼·셰이더 의존성은 없다.

동일한 Edit Mode 카메라의 교체 전후 1280×640 렌더에서 픽셀별 RGB 최대 채널 차이는 평균 0.139, 최댓값 2/255였다. 비교 캡처 `commit_sky_before.png`, `commit_sky_after.png`는 로컬 검사용이다. 앞의 Play Mode 12개 구도 검사는 플랫폼 배치에 대한 결과이며 이번 Sprite 교체 이후 재실행한 결과로 표기하지 않는다.

## 이전 흑백 시안 기록

직전 시안은 각 층 안에 검정 계열과 중성 흰색 계열 구조물을 함께 배치했다. 청회색과 베이지 기운을 제거해 배경 구조물은 RGB가 같은 회색으로 맞췄다. 실제 플레이 플랫폼의 아이보리는 유지한다. 거리에 따른 대비 감소를 표현하므로 검정 계열도 후경에서는 회색으로 보인다. 하강 구간은 왼쪽 Near의 검정 면·오른쪽 Near의 흰 면·중앙 Mid의 검정 탑·Far의 흑백 큰 면으로 구성한다.

| 층 | 검정 계열 sRGB | 흰색 계열 sRGB | 검정/흰색 타일 수 |
| --- | --- | --- | ---: |
| Near | 99, 99, 99 | 220, 220, 220 | 498 / 423 |
| Mid | 147, 147, 147 | 236, 236, 236 | 219 / 242 |
| Far | 181, 181, 181 | 218, 218, 218 | 741 / 355 |

Tilemap.color는 흰색으로 두고, 구조물별 두 색은 각 셀의 Tilemap.SetColor 값에 저장한다. 중성 타일 5종과 기존 팔레트를 그대로 사용한다. 색 경계는 큰 구조물 묶음 단위로 잡으며 체커보드처럼 잘게 번갈아 칠하지 않는다. SkyTone의 SpriteRenderer tint는 (0.864, 0.873, 0.894, 1)로 원본 이미지의 따뜻한 색을 상쇄해 중성 바탕을 만든다. 먼 킹·룩 기물 tint의 RGB는 각각 (115, 115, 115)·(244, 244, 244)이며 기존 알파는 유지한다.

앞서 넓힌 루트 높이와 단순화한 Far 윤곽, 타일 수 2,478칸은 유지한다. 새 그림·머티리얼·셰이더·런타임 코드는 없다. 1차 시안에서 흰 구조물끼리 겹쳐 윤곽이 약했던 부분은 Mid의 흰색을 밝히고 Far의 흰색을 조금 낮춰 보정했다. Far/Platforms_01은 x=16–28, Far/Platforms_02는 x=40–50을 흰 면으로 두고 나머지는 검정 계열로 배치한다. 하강 구간의 오른쪽 흰 Near와 룩 이동 구간의 흰 Near 뒤로 검정 Far가 드러나도록 하며, 작은 장식이나 윤곽선을 추가하지 않는다.

실제 Game View의 시작·하강·룩 이동 앞·긴 거리 분리·마지막 착지 5개 구도를 확인했다. Play Mode에서 각 층의 타일 색이 정확히 위의 두 종류로 유지되는 것을 확인했다. 최소 캐릭터 viewport 여백은 약 0.07, 패럴랙스 오차는 0.00000006 이하, 누락 스크립트·깨진 프리팹·Console 오류·경고는 0개다. 검증 후 물리·백그라운드 실행 설정과 카메라의 저장 위치를 복원했다. 변경은 배경 Tilemap 5개와 SpriteRenderer 3개에 한정한다. 시안과 캡처는 커밋하지 않았다.

흰 면 구분 보정 후 같은 5개 Game View를 재확인했다. 이 보정의 변경 항목은 Mid Tilemap 1개와 Far Tilemap 2개이며 Near의 색·형태, 레이어 높이, 스크롤 비율과 플레이 지형은 유지했다.

베이지 제거 시 구조물 색은 기존 밝기를 기준으로 중성 회색으로 바꿨다. 변경은 배경 Tilemap 5개와 SpriteRenderer 3개의 색에만 한정하며 타일 수·배치·알파·플레이 플랫폼·캐릭터는 유지했다.

베이지 제거 후 같은 5개 Play Mode 구도를 확인했다. 2,478칸의 저장 색 RGB 차이는 0이며, 실제 하강 캡처의 표본은 바탕 (206, 206, 205)·Near 흰 면 (219, 219, 218)·Near 검정 면 (99, 99, 99)이다. 원본 그림과 렌더링에서 남는 채널 차이는 이 표본에서 최대 1이다. 배경 밖 씬 변경, 누락 참조, Console 오류·경고는 0개다.

[Notion 아트 레퍼런스](https://app.notion.com/p/3dcb3e6e776c81f2bb63c68f908c5ec5)와 승인된 하강 구간 시안을 기준으로, 멀리 이어지는 플랫폼과 구조물을 세 거리 층으로 구성한다. 시작부터 마지막 착지까지 큰 면에 단차와 홈을 만들며 층별 폭·높이·윤곽을 다르게 사용한다.

## 저장된 에셋

플랫폼·탑·단차는 기존 배경 Tilemap과 모듈형 타일 그림으로 구성한다. Near/Far의 Platforms_01–02를 사용하고 Mid/Visual 아래에 Platforms_01 Tilemap을 추가했다. 통짜 구조물 스프라이트 12개와 대응 PNG는 제거했다. Unity URP에 포함된 Sprite-Unlit-Default 머티리얼을 참조하며 별도의 Mesh 에셋·머티리얼·셰이더는 사용하지 않는다.

총 2,478칸을 1칸 격자에 저장한다. Grid 셀 크기는 (1, 1, 0), Tilemap Transform Scale과 셀 변환은 1이다. 기존 실루엣을 격자로 옮기면서 축별 경계 위치는 최대 0.5칸 달라진다. 바깥 모서리는 기존 Round_R025 타일 네 방향으로 마감하고, 맞물리는 단차는 채움 타일로 이어 빈틈을 만들지 않는다. 가장자리는 기존 타일의 알파를 사용하며 통짜 PNG의 Mid/Far 흐림 효과는 사용하지 않는다.

기존 모듈형 Near/Far 타일은 색이 고정돼 있어 새 팔레트 색을 그대로 적용하기 어렵다. [Neutral.asset](../../Assets/TilePalette/Background/ModularTiles/Neutral.asset)에 같은 기존 Sprite를 참조하는 기본 Tile 5개를 묶었다. 채움 1개와 바깥 모서리 4개이며 새 PNG나 런타임 코드는 없다. Tile의 색은 흰색, 변환 잠금만 사용하며 Collider는 None이다. 기존 공용 타일과 팔레트는 수정하지 않았다.

편집할 때 **BG_Structure_Neutral_TilePalette**를 선택하고 위의 Tilemap을 Active Tilemap으로 지정한다. 팔레트 첫 칸은 채움, 아래 2×2 묶음은 네 방향 모서리다. 층별 색은 Tilemap.color로 조정한다. Near/Platforms_02의 마지막 플랫폼 셀에는 왼쪽 Near 색과 같아지는 작은 tint 보정이 들어 있다.

SkyTone만 Assets/Sprite/Map/Background/Chapter_01에 2×256 PNG로 남긴다. SpriteRenderer의 Sliced·크기 (105, 30)·로컬 위치 (44.5, 7)로 약한 세로 그라데이션을 표시한다. 체스 기물도 기존 스프라이트를 유지한다. 배경 Collider와 런타임 배경 생성 코드는 없다.

Far의 기물은 기존 BG_KingLandmark·BG_RookLandmark 스프라이트와 Background_Far 머티리얼을 사용한다. 킹의 로컬 위치는 (33.29, 5, 0)·크기는 1, 룩은 (49.5, −1.6, 0)·크기는 (0.8, 0.8, 1)이다. 두 SpriteRenderer의 tint는 RGB (204, 217, 224)·알파 0.32·정렬 6이다. 먼 플랫폼이 킹의 하부를 가려 받침이 공중에 드러나지 않도록 한다.

1774×887 시안의 좌표는 카메라 중심 (30.1, 1.46)·직교 크기 8·화면 비율 2:1로 환산했다. 해당 구도의 Near 오프셋은 (5.13, −0.69), Mid는 (8.55, −1.15), Far는 (11.115, −1.495)다. 탑을 Mid로 분리할 때 저작 좌표에 (+2.565, −0.345)를 보정해 주요 하강 구도의 위치를 유지했다.

## 검증

- 색·먼 윤곽 조정 후 같은 5개 Play Mode 구도를 다시 확인했다. 2,478칸의 실제 셀 색은 계획값과 일치하며, 변경된 씬 항목은 배경 Tilemap 5개이고 배경 밖 변경은 0개다. 층 루트 높이·카메라·플레이 지형·기물 참조는 유지했다.
- 세로 간격 조정 후 시작·하강·룩 이동 앞·긴 거리 분리·마지막 착지의 5개 실제 Game View를 확인했다. 캐릭터 최소 viewport 여백은 약 0.07, 패럴랙스 계산과 실측의 최대 차이는 0.00000006이며 누락 참조와 Console 오류·경고는 0개다.
- 시작·첫 통로 접근·첫 통로 양쪽·하강·문 통과·중간 평지·룩 이동 앞·긴 거리 분리·하부 복귀 바닥·공허 양쪽·마지막 착지·오른쪽 마감 벽의 12개 Play Mode 구도를 확인했다.
- 각 구도에서 캐릭터 Collider는 화면 안에 유지됐다. 최소 viewport 여백은 0.06이며 패럴랙스 계산값과 실측값은 일치했다.
- 타일맵 전환 전후 씬 항목은 280개→248개다. 통짜 구조물 GameObject 12개를 제거하고 Mid Tilemap 하나를 추가했다. 기존 Tilemap 네 개의 타일·색·위치·렌더러 설정을 바꿨으며 배경 밖 변경은 0개다.
- 타일맵 전환 전후 12개 Game View를 같은 구도로 비교했다. 큰 덩어리와 층별 색을 기준으로 확인하며 격자에 맞춘 윤곽 차이는 남는다.
- 최초 타일맵 전환 당시 Play Mode에서 2,486칸의 셀 색과 계획값을 대조한 최대 오차는 0이었다. 중성 타일 정의 5개와 팔레트의 GridPalette 설정·타일 참조를 확인했다.
- 씬의 누락 스크립트·깨진 프리팹, Console 오류·경고, 셰이더 컴파일 오류, 배경 Collider는 모두 0개다. 에셋과 폴더의 .meta도 확인했다.
- 검사 후 캐릭터 Rigidbody2D.simulated와 백그라운드 실행 설정을 복원했으며 씬은 Edit Mode·저장 완료 상태다.

- 검증 범위는 배경과 카메라 구도다. 퍼즐을 실제 입력으로 완주하는 검증은 포함하지 않는다.
